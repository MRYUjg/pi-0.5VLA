# 入口统一：夹爪 state 分派（Panda → `[:2]`，ZhiXing → `[1, 5]`）

| 项目 | 内容 |
|---|---|
| 日期 | 2026-09-27 |
| 目的 | 让默认入口 `examples/libero/main.py` 同时支持 Panda 夹爪与知行夹爪，为后续 ECO65 + ZhiXing 的进一步适配留出通道 |
| 背景问题 | `main.py` 里 state 的夹爪两位写死 `[1, 5]`（知行 6 关节取法）；换 Panda 夹爪（2 关节）会 `IndexError`，且被 `except Exception` 吞掉 → 每集第 11 步就 break，表现为"静默 0/10" |
| 结果 | 两条路均可运行、无异常：`--args.gripper PandaGripper` → **10/10**；`--args.gripper ZhixingGripper` → 0/10（不再崩溃，是真实性能问题） |

---

## 1. 背景问题回顾

`robot0_gripper_qpos` 的长度 = 夹爪关节数，顺序即 XML 声明顺序：

| 索引 | ZhixingGripper（6 关节） | PandaGripper（2 关节） |
|---|---|---|
| 0 | `gripper0_Left_1_Joint`（主动驱动） | `gripper0_finger_joint1` |
| 1 | `gripper0_Left_Support_Joint` | `gripper0_finger_joint2` |
| 2 | `gripper0_Left_2_Joint` | — |
| 3 | `gripper0_Right_2_Joint` | — |
| 4 | `gripper0_Right_1_Joint` | — |
| 5 | `gripper0_Right_Support_Joint` | — |

原 `main.py` 用 `obs["robot0_gripper_qpos"][[1, 5]]` 取知行的两个 Support 关节，凑成
`3(eef_pos) + 3(axisangle) + 2 = 8` 维，对齐 LIBERO 的 8 维协议。换上 2 关节的 Panda 夹爪后
索引 5 不存在：

```text
ZhixingGripper: 长度=6  gq[[1,5]] -> OK, [-0.91, -0.91]
PandaGripper:   长度=2  gq[[1,5]] -> ❌ IndexError: index 5 is out of bounds for axis 0 with size 2
```

而 `main.py` 的 `try` 包住整个循环体、`except Exception: break`，所以这个 IndexError **不会让程序退出**，
只会让每一集在第一次推理前就中断并被计为失败 —— 日志里仅一行
`Caught exception: index 5 is out of bounds for axis 0 with size 2`，最终得到看起来像"模型不行"的 0/10。

---

## 2. 实现

### 2.1 `examples/libero/main.py`

按**夹爪类型显式分派**（不用长度兜底，便于长期维护）：

```python
GRIPPER_STATE_SELECTOR = {
    "ZhixingGripper": [1, 5],        # 6 个联动关节，取两个 Support 关节
    "PandaGripper": slice(0, 2),     # 2 个平动指关节
    "RethinkGripper": slice(0, 2),   # 同 Panda
}


def _resolve_gripper_state_selector(env):
    """按环境里实际挂载的夹爪类型返回 (夹爪类名, state 选择器)。"""
    gripper = env.env.robots[0].gripper
    name = type(gripper).__name__
    n_joints = len(env.env.robots[0]._ref_gripper_joint_pos_indexes)
    if name not in GRIPPER_STATE_SELECTOR:
        raise ValueError(f"未登记的夹爪类型 {name}（{n_joints} 个关节）：请在 GRIPPER_STATE_SELECTOR 中补充其 state 取法。")
    sel = GRIPPER_STATE_SELECTOR[name]
    needed = max(sel) if isinstance(sel, list) else (sel.stop - 1)
    if needed >= n_joints:
        raise ValueError(f"{name} 的 state 选择器 {sel} 需要至少 {needed + 1} 个关节，实际只有 {n_joints} 个")
    return name, sel
```

要点：
- **未登记的夹爪直接报错**，不再静默退化成错误的 state；
- 每个任务建环境后解析一次，并在日志打印 `Gripper in use: xxx | state selector: xxx`（实验溯源）；
- 选择器与关节数做越界前置校验，把 IndexError 提前成可读的 ValueError。

同时新增可选参数，使两条路都能直接从命令行切换，而无需改类的默认值：

```python
gripper: str = "default"   # default | PandaGripper | ZhixingGripper | RethinkGripper
```

`_get_libero_env(task, resolution, seed, gripper="default")` 在 `gripper != "default"` 时
传入 `gripper_types`；`default` 保持原行为（用机器人类的 `default_gripper`）。

state 构造改为：

```python
obs["robot0_gripper_qpos"][gripper_state_sel],
```

### 2.2 `agent-work-space/scripts/eval_matrix.py` 同步统一

评测脚本原先用长度启发式（`len>=6` 取 `[1,5]`，否则 `[:2]`），现改为与 `main.py` **同一套**
`GRIPPER_STATE_SELECTOR` + `resolve_gripper_selector()`，避免两处约定漂移。

### 2.3 改动清单

| 文件 | 改动 | 备份 |
|---|---|---|
| `examples/libero/main.py` | 新增选择器与解析函数、`--args.gripper`、state 改用选择器 | `main.py.pre_gripper_entry.bak` |
| `agent-work-space/scripts/eval_matrix.py` | 同上约定 | `eval_matrix.py.pre_gripper_entry.bak` |

## 5. 边界

- 状态数值仍**不进入网络条件**（`pi05_libero` 为 `discrete_state_input=False`），夹爪两位只参与接口形状与归一化；
  但索引必须与当前夹爪一致，否则同样会崩。
- 知行夹爪的 `[1, 5]` 是**旋转的 Support 关节角**，Panda 的 `[:2]` 是**平动指关节位置**，物理含义不同；
  这属于接口层面的对齐，不等于完成了 ECO65 + ZhiXing 的语义适配。
- 默认入口（不带 `--args.gripper`）仍使用类的 `default_gripper = "ZhixingGripper"`；若要改默认值，
  需同步修改 `eco65_robot.py` 与 `mounted_eco65.py` 两处（本轮未改，避免影响其他入口）。
