**前缀链路已核对**：XML 里用未加前缀的 `base` / `link_1`；`MujocoXMLModel.__init__` 会调用
`add_prefix(root, prefix="robot0_", exclude=exclude_from_prefixing)`，而 `MUJOCO_NAMED_ATTRIBUTES` 含
`body1`/`body2`，且 `MujocoXMLModel.exclude_from_prefixing` 恒返回 `False` → 编译后正确变成
`robot0_base` / `robot0_link_1`。`MujocoXML.merge()` 也会把 `<contact>` 合并进场景 XML。

## 4. 这个结果回答了"π0.5 不绑定机械臂，为什么换臂会变差"

之前 `换机械臂为何变差_分析.md` 把主因归到**观测分布**（手臂外观、腕部尺度、初始位姿）与**6-DOF 非冗余**，
并明确标注其中"起始位姿差 → 尺度失真 → 策略误判"这条链是**推断**。本轮结果需要修正这条判断：

> π0.5 的**接口**确实本体无关（图像 + 语言 → 末端位姿增量 + 夹爪标量），
> 但它是一个**闭环控制器**：它默认"我发出的末端增量会被真实执行"。
> ECO65 当时的问题不是"模型不适配这个臂"，而是**这个臂没有执行模型发出的指令**。

实测：下令世界 y 方向 +20 mm，实际只走 **+3.44 mm**（约 1/5 行程），且不触发力矩限幅、不到关节限位；
排除基座—第一连杆碰撞后同一测试降到 0.6 mm。也就是说，闭环里"我发出 a → 我看到 o′"这一步的
**plant 是坏的**，策略无法通过视觉反馈收敛。

修复后同权重、同协议下成功率 0/10 → 6/10，证明：

| 因素 | 修复前贡献 | 修复后残留 |
| --- | --- | --- |
| 机械臂执行不准（基座自碰撞） | **主因**（足以单独造成 0/10） | 已消除（26/32 控制项通过） |
| 观测分布差（外观 / 腕部尺度 / 初始位姿 8.7 cm / 6-DOF 非冗余） | 被主因掩盖，无法单独量化 | **残留 60% → 100% 的差距** |
| 知行夹爪 | 独立致败因素 | **仍独立致败**（G 格 0/10） |

因此现在可以这样表述：**"跨本体迁移失败"在这台机器上有两个可分离的原因——执行层缺陷（已修复）
与分布层差异（仍需对齐或微调）**；而"模型不绑定机械臂"只在接口层成立，不代表权重能容忍 plant 被破坏。
