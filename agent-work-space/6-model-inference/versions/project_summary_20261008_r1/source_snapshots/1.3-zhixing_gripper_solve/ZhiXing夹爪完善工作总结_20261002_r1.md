# ZhiXing夹爪完善工作总结

版本：r1｜日期：2026-10-02  
对象：ECO65机械臂＋ZhiXing夹爪；当前服务器为纯CPU。  
工作目录：`/mnt/data/vla-policy/openpi/agent-work-space/zhixing_gripper_solve`

## 1. 当前结论

**已经通过仿真验证：ZhiXing夹爪能够完成物体抓取、悬空保持、搬运、松爪和稳定投放。** 这项能力已经在诊断试块和LIBERO原生碗、罐模型上得到实测支持。

最新锁定候选、采用未使用种子的独立测试结果是：**罐10/10，碗8/10**。碗的两例失败分别发生在初始化和抓取前接近阶段，并不是抓住后夹不稳或不能松爪。

因此，可以确认“夹爪具备完成抓放任务的能力”；但尚不能确认“整套适配方案已经稳定达到验收要求”。本阶段要求每类至少9/10，碗未达标。十个Spatial任务各20次、π0.5微调及实机部署也尚未完成。

这里的“原生碗、罐”指使用LIBERO实际任务中的仿真物体资产，不是实物实验。本阶段教师是生成机械臂控制动作的脚本，不是π0.5模型。

## 2. 初始表现：能动、部分能夹起，但完整抓放不可靠

最初的问题不能简单概括成“夹爪没有力量”。当时混合存在开合速度配置、测量口径、教师路径、运动跟踪和仿真环境问题，需要逐项拆开。

| 初始现象 | 后续查明的问题 | 对任务的影响 |
|---|---|---|
| 不同入口的开合表现不一致，快速闭合时闭环残差较大 | 夹爪资产旧默认速度为0.2，而部分运行入口显式使用0.01 | 相同模型可能因入口不同得到不同结果 |
| 空载闭到底后执行器输出很小，被理解为“几乎没有夹持力” | 把空载端点状态外推到了带载抓持；还混用了转动力矩与直线力单位 | 对夹爪能力的判断失真 |
| 能抬起试块，但搬运后落在篮外 | 载荷未越过篮沿就横移，碰撞推走篮子；教师仍向旧坐标投放 | 抓持成功被后续路径错误破坏 |
| 有些样本在抓取前就被规划器拒绝 | 用稀疏网格顶点近似抓取截面，可能选到错误截面 | 尚未尝试抓取就失败，不能归为夹不住 |
| 增加抬升高度后仍无法到位 | 长夹爪改变TCP偏移、外形包络及可达姿态；还存在控制冲突 | 几何上“抬高”并不保证实际可执行 |
| 仿真完成后进程异常退出 | 原运行时存在退出码139/134异常 | 结果链路不可靠，不能只看中间日志宣称通过 |

可作为可靠起点的带载诊断是2026-10-01的正式批次：ZhiXing在三个试块场景中都能抬升并保持，但旧教师完整抓放为**0/3**，释放结束时篮子移动约**61–109 mm**。[带载诊断记录](带载测量与分阶段定位_20261001_r1.md)

更早速度试验中的汇总夹杂历史运行时及记录器问题，本总结不把那些失败率与后续正式批次拼接成统一成功率。

## 3. 完善工作一：统一开合速度，核清控制含义

### 问题与处理

此前已按用户要求，将`ZhixingGripper.speed`的资产默认值从**0.2改为0.01**，保留环境变量覆盖能力，使未显式设置速度的入口也使用经过验证的值。

同时核清：这个参数是内部目标的累积步长，不是毫米/秒；`format_action`在每个物理子步调用，不能把它误认为只在20 Hz控制步调用一次。当前动作极性为−1张开、+1闭合，零命令保持内部累积目标。

### 验证效果

使用同一N1体检脚本复测，记录如下：

| 指标 | 旧默认0.2 | 新默认0.01 |
|---|---:|---:|
| 四连杆闭环最大残差 | 17.372 mm | 约0.091 mm |
| 指垫自接触穿透 | 约0.0995 mm | 约0.0005 mm |

这解决了默认速度与已验证运行配置不一致的问题，改善了该体检条件下的闭环表现。它**没有单独解决完整抓放问题**；原N3/N4等显式设置0.01的入口，实际速度并未因这次默认值变更而改变。

历史速度记录末尾关于“端点无力”等推断已被后续带载测量纠正，不能继续作为当前结论。[历史速度变更证据](evidence/_history_速度默认值改动记录_20260930.md)

## 4. 完善工作二：建立可信的带载测量，纠正“夹爪无力”的判断

### 做了什么

建立逐物理步记录器，记录左右手指接触力、穿透、物体相对TCP滑移、其他支撑接触、动作前后状态与真实进程退出码。每次运行先用1 kg静止方块校准，确认支持力约为9.81 N。

测量时实际夹起物体、保持2秒，并确认双侧接触持续存在、没有桌面或篮子支撑。还修正了Panda对照中手指碰撞子树的分类遗漏，避免把正常手指接触误算为外部支撑。

区分了两种物理量：ZhiXing转动执行器的输出单位是N·m，Panda平动执行器是N；两者不能直接比较数字大小，应比较实际指端接触力及抓持效果。

### 解决后确认了什么

在同一seed=47101、0.0882 kg诊断试块的2秒保持阶段：

| 指标 | ZhiXing | Panda对照 |
|---|---:|---:|
| 左指平均法向力 | 12.27 N | 14.87 N |
| 右指平均法向力 | 11.36 N | 14.87 N |
| 双侧有效接触比例 | 100% | 100% |
| 非手指支撑 | 无 | 无 |
| 最大相对滑移 | 1.852 mm | 0.115 mm |

**结论从“怀疑没有夹持力”改为“已测得持续带载夹持力，但该条件下滑移大于Panda”。** 这是测量与判断的纠正，并不是通过提高力限制造出的结果。

还进行了0、2、5、10 N的单方向抗扰诊断。ZhiXing前三档满足本次保持标准，10 N时滑移5.892 mm，超过5 mm阈值；Panda该档为2.384 mm。每档仅一次，不能据此声称ZhiXing的极限夹持力只有5 N，也不能把超滑移阈值直接写成脱落。后续路径成功不等于这项抗扰差距已被解决。[测量口径](测量口径与运行环境_20261001_r2.md)

## 5. 完善工作三：恢复可复核的CPU诊断运行环境

原Python3.8环境在进程退出时出现139/134异常；关闭渲染、JIT或传感器未能消除。为继续验证，建立隔离的Python3.10依赖环境，正式数值诊断统一使用MuJoCo3.2.6。

正式带载诊断的14个独立进程全部正常退出，原始数据可重新计算汇总指标。后续试块和原生物体批次也保存实际退出状态，不用强制退出隐藏异常。

解决的是**隔离、无渲染CPU诊断链路的可用性**。原环境内存异常的唯一根因、生产环境及CPU图像渲染稳定性，不能据此宣称已经修复。不同引擎版本的受力结果存在差异，因此没有混合统计。

## 6. 完善工作四：按ZhiXing实际几何重写安全教师路径

### 怎样定位旧路径失败

以旧教师seed47100为例：物体仍被夹住时就碰到篮子侧壁；当时物体最低点约115 mm，篮沿约141 mm，尚未越过篮沿。篮子被推移，机械臂搬运也未到位，教师却继续朝原先计算的投放点释放，最后物体落在篮外。

这说明失败不能全归因于夹持力。ZhiXing较长的工具外形、夹持偏移以及载荷底部，都必须进入路径计算；只关注TCP点或直接沿用旧高度不足以保证安全。

### 具体修正

1. 从加载模型读取实际TCP：`gripper0_grip_site`相对安装体约为`[0,0,0.20254] m`，不重复叠加失效的历史偏移。
2. 分别测量夹爪完整外形、有效碰撞几何与被夹物体的包围盒；视觉外形用于保守避让，但不把视觉网格误认为已经启用碰撞。
3. 抓起后重新测量实际带载包络，以篮沿高度、工具姿态及整体最低点计算安全高度，规划余量40 mm，实际横移净空至少10 mm。
4. 搜索可达的搬运倾角，对垂直终点、横向路径中间点及下降终点进行逆解预检；预检在独立运动学副本中执行，不向运行中的仿真写入关节姿态。
5. 严格执行“垂直抬升到位→横向搬运到位→下降到释放位置→松爪→稳定检查”。姿态变化后重新测量物体偏移，修正搬运和投放目标。
6. 任何阶段未实际到位、净空不足、发生非预期接触或篮子位移超过5 mm，都停止并记录失败，不继续向旧坐标投放。

这里的投放是在计算的安全高度释放，由重力落入接收区域并验证稳定；不代表已经实现夹爪深入容器的精密贴底放置。

### 解决后效果

| 试块路径指标 | 旧教师 | 新安全教师 |
|---|---:|---:|
| 相同三个旧失败场景完整抓放 | 0/3 | 3/3 |
| 最终开发回归 | — | 5/5 |
| 锁定代码后的新增初态 | — | 10/10 |
| 篮子位移 | 释放末约61–109 mm | 新教师净空抬升起最大约0.036 mm |
| 横向搬运最小净空 | 已发生碰篮沿 | 34.45 mm |

新教师15个样本中，记录的释放前机器人/载荷碰篮、夹爪碰非目标环境的接触力峰值均为0。该对比同时包含几何路径、姿态、到位保护和教师动作修正，不是仅改变一个因素的消融实验。[安全教师实现记录](安全教师路径_实现与验证记录_20261002_r1.md)

此外，试块规划器从“抓取平面附近的稀疏顶点采样”改成“box边与平面的真实交点”，修复了错误截面导致的规划拒绝。早期因此失败的样本没有删除。

## 7. 完善工作五：从试块扩展到LIBERO实际碗、罐几何

试块成功后，没有直接把同一抓点算法套用到所有物体，而是读取原生物体碰撞模型重新规划。

| 物体 | 几何特点 | 采用的抓取方式 |
|---|---|---|
| alphabet_soup罐 | 21个碰撞盒，外包围盒约62.9×62.5×76.2 mm | 规划整体夹持 |
| akita_black_bowl碗 | 40个碰撞盒描述碗壁与底部；外径约107 mm，大于当前夹爪开口约89.6 mm | 规划局部碗沿夹持，保留碗腔空隙 |

实现了射线与各碰撞盒的精确求交及占据区间合并，使规划器识别“哪里有实际材料、哪里是空腔”。对倾斜碗增加物体坐标系上缘表面候选和张开夹爪接近路径碰撞检查；闭合后还要确认持续双侧接触，才能进入抬升。

原生物体资产未被诊断试块替换，也没有为获得成功而强制摆正倾斜碗。完整过程继续接受实际到位、净空、接触、穿透、悬空保持和释放后任务条件检查。

## 8. 完善工作六：隔离验证额外PD冲突，修正教师过冲与振荡

### A/B验证了什么

发现ECO65在OSC末端控制之外，还有把关节拉回`init_qpos`的额外关节PD；该力矩直接叠加，没有经过任务零空间投影，因此可能干扰末端任务。

经用户授权，使用同一教师、相同初始qpos、资产和门限进行配对A/B：两组均先在legacy下初始化，静置后才在B组切换已有`eco65_no_extra_pd`，将额外kp从3改为0，相应额外阻尼也变为0。

| 对照范围 | A：额外kp=3 | B：额外kp=0 |
|---|---:|---:|
| 三个困难碗场景完整任务 | 0/3 | 1/3 |
| 一个罐场景完整任务 | 1/1 | 1/1 |

B组的三个碗场景都通过了旧的抬升/搬运阻塞阶段，但两例随后在下降或松爪时发生非预期接触。由此确认该PD项影响了这些场景的跟踪，**单独关闭PD仍不足以解决全部问题**。

### 后续教师修正

逐步轨迹显示，旧教师的积分补偿、较强的姿态增量放大，以及“瞬时进入误差范围就切换阶段”，在新控制配置下会留下过冲和振荡风险。

经过保留失败样本的开发回归，最终r20对碗采用：关闭kp0条件下的教师积分补偿；减小旋转误差到动作的放大；连续5步满足原位置/姿态门限，且实际TCP每步位移小于0.5 mm，才切换阶段。罐保留已经通过的原教师行为，避免把碗的调整直接套到罐上。

最终统一候选先通过三个碗及一个罐的回归，再锁定源码进行新种子测试。没有修改OSC增益、底层动作单位、力矩限值或碰撞资产；本阶段使用隔离运行时profile，没有切换生产默认控制配置。此前速度默认值变更属于另一项已登记的历史改动。

最终效果来自控制配置与教师修正的组合，不能全部归功于取消PD。[A/B执行记录](控制配置_AB执行与定位记录_20261002_r1.md)

最新批次为`real_objects_validation_20261002_r3`，使用锁定的r20教师和新种子52100–52109，两类各10次，失败不替换、不补抽。

| 指标 | 罐 | 碗 |
|---|---:|---:|
| 完整抓取—保持—搬运—投放成功 | **10/10** | **8/10** |
| 成功样本2秒保持阶段最低双侧接触比例 | 100% | 100% |
| 成功样本保持阶段其他支撑力 | 0 N | 0 N |
| 成功样本最大指接触穿透 | 0.308 mm | 0.500 mm |
| 成功样本最大TCP单步实际位移 | 7.038 mm | 10.601 mm |
| 成功样本横向搬运最低净空 | 35.743 mm | 23.528 mm |

这些数据证明成功样本中的物体是由两侧手指持续夹持、悬空搬运并最终释放，而不是依靠桌面或容器支撑伪装成抓取。

本批审计了325,025个物理步。原始教师执行监测区间内，非目标机器人接触（>0.1 N）及保护规则判定的非法接触计数均为0；**这一统计不覆盖全部初始化与静置区间，不能理解为整集没有碰撞**。

阶段结果应分开理解：

| 阶段 | 结果 | 可以支持的结论 |
|---|---|---|
| 旧试块教师诊断 | ZhiXing完整抓放0/3，但能抬起保持 | 旧失败不全是夹持能力问题 |
| 新试块安全教师 | 回归5/5；新增初态10/10 | 已解决这些试块场景的完整路径问题 |
| 原生碗罐第一轮新种子 | 罐10/10、碗5/10 | 实际几何接入后仍有跟踪问题 |
| 原生碗罐第二轮新种子 | 罐10/10、碗8/10 | 部分跟踪改善，仍有失败 |
| r20最新新种子 | 罐10/10、碗8/10 | 已具备原生物体抓放能力，但两类各≥9/10的门槛未通过 |

不同阶段使用的对象、种子、教师和部分运行条件不同，不能合并成一个总成功率，也不能把“仍为8/10”理解为完全没有改善；必须同时看失败发生在哪个阶段。最新统计也不能证明泛化成功率一定为80%或100%。[最新数值汇总](evidence/real_objects_summary_20261002_r3.json)

## 10. 尚未解决的问题

### 10.1 初始化无效：seed52103

该例最初表现为“无可行抓点”，追溯发现碗在教师开始前已经掉到桌外地面。新增观察式探针复现了reset至120步静置的全过程：reset时碗与盘子已经穿插约10.82 mm，随后被接触反力弹出桌面。复现静置后的全部qpos哈希与原失败初态完全一致。

这是初始化几何有效性问题，不是夹爪夹不住。已定位到穿插—弹出—不可达的链路，但尚未修复初始化流程；进一步追到具体采样器原因仍需工作。该例仍计入碗的10次测试分母。

### 10.2 接近未到位：seed52104

碗仍在桌上，离线逆解通过，但实际接近位置误差约10.80 mm，超过4 mm门限；尚未闭合或抬升。已经定位到位置跟踪残差，尚未完成针对性修复。

### 10.3 其余验证边界

- 当前原生任务罐的目标初始位置基本固定，10个场景种子不等于10个不同抓取位置。
- 原生仿真罐约25.85 g、碗约5.59 g；不能据此证明真实重物负载能力。早期88.2 g试块抗扰结果也不能直接外推到其他形状。
- 早期ZhiXing相对Panda更大的滑移和10 N抗扰不通过，尚无证据表明已由路径修改解决。
- 成功轨迹仍需做平滑性、图像、动作/状态一致性及回放质量检查，才能作为训练数据；任务成功不等于数据已放行。
- 尚未完成全部Spatial任务、π0.5微调与推理评测、实机抓放及精密贴底放置验证。
