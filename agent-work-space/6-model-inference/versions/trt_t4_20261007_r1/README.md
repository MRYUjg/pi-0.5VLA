# TensorRT T4 开发闭环与当前设备资源验证

版本：`trt_t4_20261007_r1`。本目录接续冻结的 T3，原有模型、引擎、校准数据、结论与失败项全部保留。本次用户授权原始模型、同环境 float、AWQ 和 GPTQ 的 Panda+PandaGripper LIBERO 闭环比较，并先在当前 4090 上检查完整单模型推理路径资源。

本轮四组各 1,000 次连续推理、120 集主闭环与四次单客户端延迟探针已完成。AWQ 为 26/30，与 float 相同，但未达 27/30 门槛；GPTQ 为 25/30，旧离线未通过项保留。124 个视频、16,434 帧完整回读通过。正式结果见 [T4闭环与资源对比记录](T4闭环与资源对比记录.md) 与 `runs/trt_t4_20261007_r1/report_r1/summary.json`，文件冻结不表示部署验收通过。

## 固定实验范围

- 原始参考为同源原始 `pi05_libero` 权重及原 PyTorch 采样实现；没有测量 JAX 后端性能。
- 比较组为 `original_torch`、`trt_float`、`awq`、`gptq`，权重和 engine 均来自冻结 T0–T3。
- LIBERO Spatial 10 个任务，每任务使用官方初态索引 0、1、2，共 30 集／模型，四组 120 集。它们未用于此前校准，正式最后 20 个初态继续保留。
- 固定种子 `940000 + 100*task + init_index`；每次重规划噪声种子为 `episode_seed*1000 + replan_index`。
- 保留原 20Hz 仿真控制、10 步初始化等待、最多 220 个策略步、每 5 步重规划、10 次去噪、10×7 环境动作。记录收到的 FP32 原始动作，再按原参考方式 `np.clip` 后执行；判定仍为环境 `_check_success()`。
- GPU 模型逐组运行，每组只有一套模型。闭环使用两个 CPU 仿真工作进程，另做四组单客户端延迟探针；探针复用 task0/init0，只用于链路测量，不增加成功率分母。
- T4 闭环门槛仍为 ≥27/30、相对 TensorRT float 净损失 ≤1 集。旧数值门槛不变，GPTQ 已知未通过项不自动豁免。

## 资源和证据

各组先完成 20 次暖请求及 1,000 次真实观测连续请求，重放原 128 观测并在连续运行后重复第一观测。NVML 在宿主以 20ms 间隔从容器启动前采样，保存字节级设备总用量和政策进程用量，覆盖导入、加载、预热和运行。连续请求早／晚区段用量增长门槛为 64MiB，仅作本轮开发稳定性筛查。

资源请求的延迟包括本地 HTTP、解码、原预处理、完整模型、反归一化和返回，另列 vision/prefix/action_step CUDA event 时间。资源请求使用已捕获图像，不含真实相机采集；闭环和单客户端探针保存仿真步／渲染与相机到动作耗时。首个重规划包含场景审计、视频初始化等成本，与后续请求分列，同时保留全部请求统计，不替换原门槛。

两小时连续测试、目标 4070/8GB、正式 200 次与实机均未执行。当前设备资源筛查通过不等于目标设备验收。

| 脚本 | 用途 |
|---|---|
| `preflight.py` | 登记 30 个初态、控制器与仿真环境，验证编码／解码与退出 |
| `common.py`、`models.py`、`server.py` | 冻结来源核验、单模型推理服务与不改变运算的计时 |
| `memory.py`、`resources.py`、`benchmark_client.py` | 宿主完整生命周期 NVML 与串行 1,000 请求 |
| `closedloop.py`、`run_closedloop.py` | 固定场景闭环、逐步动作、双相机 MP4 与真实退出码 |
| `latency_probe.py`、`run_latency_probe.py` | 单客户端相机链路测量，独立记录重复场景 |
| `verify_dependencies.py` | 对照 T3 检查包版本、源码、补丁与 tokenizer |
| `report.py` | 初态指纹对齐、配对丢失／恢复、固定输入动作误差与实际成功率 |
| `audit_artifacts.py` | 完整解码 124 个视频、重新验证保存的初态与动作序列 |
| `freeze_release.py` | 新清单及服务器完整／本地部分镜像校验 |

每次运行保存独立源码快照、命令、日志和真实退出码。报告对旧 pilot 及 30 个相同初态第一观测分别比较数值；输入已因轨迹分化而不同的后续动作，不伪装成同输入的量化误差。

冻结后不要把输出写回本版本，也不要直接重启已有服务容器：它们的输出目录已存在，脚本会拒绝覆盖。复现须建立新版本或新的输出目录、容器名；复用当前只读 engine，依然一次加载一套模型。所有控制、采集和原审计源码保持原样。
