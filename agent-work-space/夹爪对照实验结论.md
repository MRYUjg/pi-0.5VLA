# 夹爪消融实验：评测效果差是夹爪造成的吗？

| 项目 | 内容 |
| --- | --- |
| 日期 | 2026-09-26 |
| 环境 | 服务器 `galaxy-mobile`，Docker 镜像 `libero` + `openpi_server`（Docker 部署见 `docker_配置步骤.md`） |
| 模型 | `pi05_libero`（官方 π0.5 LIBERO 微调权重，为 **Panda + PandaGripper** 训练） |
| 策略服务 | `scripts/serve_policy.py --env LIBERO`，`discrete_state_input=False`（状态数值不进网络） |
| 评测脚本 | `agent-work-space/scripts/eval_matrix.py`（`examples/libero/main.py` 的参数化版本） |
| 评测集 | `libero_spatial`，10 个任务 × 1 次 rollout，`seed=7`，`replan_steps=5`，`num_steps_wait=10` |

---

## 1. 结论

**夹爪确实是原因之一，但不是唯一原因。**

把知行夹爪装到表现最好的 Panda 机械臂上，成功率从 **10/10 直接掉到 0/10**；反过来把 ECO65 换成 Panda 夹爪，仍然是 **0/10**。
也就是说：**夹爪和机械臂各自都足以把评测打到 0**。

全部使用**同一份脚本、同一 seed、同一任务集、同一随机初始化协议**（除注明外）。

| B | ECO65 | **PandaGripper** | random | **0/10** | 只换夹爪 → 无改善 |
| C | Panda | PandaGripper | init_state（官方） | 8/10 | 阳性对照 |

| E | **Panda** | **ZhixingGripper** | random | **0/10** | 只换夹爪 → 崩掉 |

2×2（都用 random 初始化，可直接对比）：

|  | PandaGripper | ZhixingGripper |
| --- | --- | --- |
| **Panda** | **10/10** | **0/10** |
| **ECO65** | **0/10** | **0/10** |

推论：

1. **阳性对照成立**：同一套服务端、同一套图像预处理、同一套动作执行，Panda+PandaGripper 拿到 10/10（官方 `libero_spatial` 为 98.8），说明**链路、权重、评测脚本都是正确的**，0% 不是环境或脚本问题。
2. **夹爪是充分致败因素**：D → E 只改了夹爪，10/10 → 0/10。
3. **机械臂也是充分致败因素**：D → B 只改了机械臂，10/10 → 0/10。
4. **初始化方式不是原因**：C（官方初始状态）8/10 与 D（随机初始化）10/10 同量级；A/B 用了与 D 相同的随机初始化仍为 0/10。

## 3. 机制线索

### 3.1 策略输出的夹爪指令被"带偏"

`diag_trajectory.py` 记录每个 replan 周期策略输出的第 7 维（夹爪）指令：

| 配置 | t=10 → t=65 的夹爪指令 |
| --- | --- |
| Panda + PandaGripper | `-1.00 … -1.00`（保持张开）→ 到位后 `+1.00`（闭合） ← **正常的抓取时序** |
| Panda + ZhixingGripper | **`+1.00` 全程**（从第一步就一直闭合） |

因为 `pi05_libero` 是 `discrete_state_input=False`，**夹爪指令完全由图像决定**。装上知行夹爪后腕部相机看到的画面变了，策略就一直输出"闭合"——爪子还没碰到物体就已经闭上，自然抓不到。

### 3.2 末端轨迹本身是合理的

| 配置 | 末端总位移 | 轨迹范围 | 动作幅度均值 |
| --- | --- | --- | --- |
| Panda + PandaGripper | 0.275 m | (0.195, 0.134, 0.244) | 0.208 |
| Panda + ZhixingGripper | 0.351 m | (0.239, 0.152, 0.211) | 0.218 |
| ECO65 + ZhixingGripper | 0.269 m | (0.252, 0.062, 0.123) | 0.224 |
| ECO65 + PandaGripper | 0.145 m | (0.125, 0.040, 0.168) | 0.193 |

机械臂**确实在朝桌面移动**、动作幅度与正常配置相当，不是"乱动"。失败发生在抓取与放置的几何/时序环节。

### 3.3 画面证据

`agent-work-space/eval/_compare/` 下的关键帧：

- **ECO65 + 知行（失败）中段帧**：夹爪趴在盘子边缘、没有夹住黑碗，肘部深度折叠（接近工作空间边界）。
- **Panda + PandaGripper（成功）末段帧**：夹爪正夹着黑碗放到盘子上。
- 腕部视角对比：两者都是俯视桌面、夹爪位于画面下方，但 ECO65+知行 的画面下方被夹爪本体占据的比例明显更大（相机相对手指的距离/尺度不同）。

## 4. 为什么知行夹爪会破坏评测（候选原因，按可能性排序）

1. **腕部相机的视觉分布偏移**（最可能）：`robot0_eye_in_hand` 挂在机械臂 hand body 上，而夹爪指长/外形/开口与 Panda 夹爪差异显著；策略完全依赖图像，看到没见过的夹爪就输出错误的夹爪时序。实验证据见 3.1。
2. **夹爪开合速度差 20 倍，且知行夹爪在单个 env step 内就饱和**（v2 更正，见文末勘误）：
   三个夹爪的 `format_action` **都是累加式**（`u += speed·sign(a)`，再 clip 到 [-1,1]），差别在 `speed` 与调用频率：

   | 夹爪 | speed | `format_action` 调用频率 | 每个 env step 的 u 变化 | 全行程 (-1→+1) 需要 |
   | --- | --- | --- | --- | --- |
   | `PandaGripper` | 0.01 | 25 次（每个 sim substep 一次） | 0.25 | **8 个 env step**（0.4 s，可调制） |
   | `RethinkGripper` | 0.01 | 25 次 | 0.25 | 8 个 env step |
   | **`ZhixingGripper`** | **0.2** | 25 次 | **5.0** | **0.4 个 env step** —— 一步之内从全开打到全闭 |

   调用频率依据：`env.step()` 以 `control_timestep/model_timestep = 0.05/0.002 = 25` 个 substep 循环，
   每个 substep 调用 `_pre_action` → `RobotEnv._pre_action` → `robot.control()` → `grip_action()` → `format_action()`
   （`robosuite/environments/base.py:391`、`robosuite/environments/robot_env.py:558-584`、`robosuite/robots/single_arm.py:268`）。

   即：**知行夹爪实际上是 bang-bang 的**，策略只要输出一次"闭合"，夹爪在 50 ms 内闭死，没有任何可调制的中间态。
3. **指长/夹持点几何不同**：策略学到的"下降到位→闭合"高度是按 Panda 指尖位置学的；知行指尖位置不同会抓空或顶飞物体。
4. **`init_qpos` 不自洽**（次要，已记录）：`ZhixingGripper.init_qpos` 只有一个元素 `[-0.91]`，被广播到 6 个夹爪关节，与 XML 里 5 条 equality 约束的初始关系不符，reset 后需要求解器消除偏差。

## 勘误（v2，2026-09-26 修订）

**原文错误**：§4 第 2 条曾写成"`ZhixingGripper.format_action` 是累加式，而 `PandaGripper` 由 position actuator 直接跟随"。

**这是错的。** 核查 robosuite 1.4.1 源码后确认：

- `PandaGripper.format_action`（`robosuite/models/grippers/panda_gripper.py:43-58`）同样是累加式：
  `self.current_action = np.clip(self.current_action + np.array([-1.0, 1.0]) * self.speed * np.sign(action), -1.0, 1.0)`，`speed = 0.01`。
- `RethinkGripper` 同样（`rethink_gripper.py:43-58`，`speed = 0.01`）。
- `ZhixingGripper`（`zhixing_gripper.py:49-58`）结构相同，但 `speed = 0.2`。

**更正后的结论**：差异不在"累加 vs 直接跟随"，而在 **speed 相差 20 倍 + 每个 env step 被调用 25 次**，
导致知行夹爪在**单个 env step 内就饱和**（u 变化 5.0，远超 [-1,1] 全程 2.0），实际等效于 bang-bang；
而 Panda/Rethink 需要 8 个 env step 才能走完全程，是可控的渐变。

这**加强**而不是削弱了"夹爪动力学是致败因素"的判断，但对"为什么"的解释变了：
不是"同样的时序曲线不同"，而是"**知行夹爪没有中间态，任何一次闭合指令都会瞬间闭死**"。

**其余结论不受影响**：策略输出的夹爪指令序列（Panda 上为 -1→+1，知行上全程 +1）、2×2 成功率矩阵、
以及"状态不进网络、行为差异只能来自图像"这条推断链，都基于独立的实验数据。

## v3 补充：夹爪开合速度消融（2026-09-26）

### 动机

v2 勘误发现 `ZhixingGripper.speed = 0.2`，而 `PandaGripper`/`RethinkGripper` 都是 `0.01`；
再考虑 `format_action` 每个 env step 被调用 25 次（25 个 sim substep），知行夹爪的 u 每步变化 5.0，
**一个 env step 内就饱和**（bang-bang），而 Panda 需要 8 个 env step。于是提出假设：
**知行夹爪失败是因为开合太快、没有中间态**。

### 做法

把 `ZhixingGripper.speed` 改为可通过环境变量覆盖（默认仍 0.2，不影响既有行为）：

```python
# robosuite/models/grippers/zhixing_gripper.py
@property
def speed(self):
    # [server-local] 可通过环境变量覆盖，用于夹爪开合速度消融实验；默认 0.2 = 原实现。
    return float(os.environ.get("ZHIXING_GRIPPER_SPEED", "0.2"))
```

然后跑两格，speed 设为 **0.01**（对齐 Panda）：ECO65+知行、Panda+知行。

**覆盖生效已验证**：容器内 `ZhixingGripper().speed` 在无环境变量时为 `0.2`，带 `ZHIXING_GRIPPER_SPEED=0.01` 时为 `0.01`。

### 结果：假设被推翻

| tag | 机械臂 | 夹爪 | speed | 初始化 | 结果 | 有效性 |
| --- | --- | --- | --- | --- | --- | --- |
| A | ECO65 | ZhixingGripper | 0.2 | random | 0/10 | ✅ |
| **F** | **ECO65** | **ZhixingGripper** | **0.01** | random | **0/10** | ✅ |
| B | ECO65 | PandaGripper | — | random | 0/10 | ✅ |
| C | Panda | PandaGripper | — | init_state | 8/10 | ✅ |
| D | Panda | PandaGripper | — | random | **10/10** | ✅ |
| E | Panda | ZhixingGripper | 0.2 | random | 0/10 | ✅ |
| **G2** | **Panda** | **ZhixingGripper** | **0.01** | random | **0/10** | ✅ |

- **F = A = 0/10**：把知行夹爪速度调到与 Panda 一致，ECO65 上毫无改善。
- **G2 = E = 0/10**：在本来 10/10 的 Panda 上，知行夹爪无论快慢都是 0/10。

→ **开合速度不是致败原因。** 它是一个真实的差异（bang-bang vs 可调制），但不是失败的原因。

### 为什么速度改了也没用

`diag_trajectory.py` 记录的是**策略输出的夹爪指令**（`chunk[0][6]`），speed 只影响这条指令的**执行快慢**，不影响策略的**决策**。
实测：speed=0.01 时策略在 Panda+知行 上依然**从第一步起就持续输出 `+1`（闭合）**，与 speed=0.2 时完全一致。

即因果链是：

```text
腕部画面里是知行夹爪（外观与训练分布不同）
        └─→ 策略持续输出"闭合"（决策层面的偏移）
                └─→ 爪子还没碰到物体就已经闭上
                        └─→ 抓空 → 0/10
```

speed 处于这条链的**下游**（只决定闭得多快），所以改它无效。

### 更新后的归因

| 因素 | 状态 |
| --- | --- |
| 夹爪开合速度（0.2 vs 0.01） | ❌ **已排除**（本轮消融） |
| 夹爪/机械臂的**视觉外观**导致策略输出偏移 | ✅ 有直接证据（指令序列从 -1→+1 变成恒 +1） |
| 夹爪**几何**（`grip_site` 距基座 0.12 m vs Panda 0.097 m、指长/指宽不同） | ⚠️ 仍可能（未单独隔离） |
| 夹爪**接触力学**（1 个 actuator kp=100 + 5 条 equality 联动 vs 2 个 actuator kp=1000 + 限力 ±20 N） | ⚠️ 仍可能（未单独隔离） |
| `init_qpos` 单值广播到 6 关节 | ⚠️ 仍可能（次要） |

### 方法论提醒（本轮踩到的坑）

第一次跑 G 格时漏了 `--init-mode random`，Panda 装知行夹爪后模型 nq 从 **39 变 47**，
`set_init_state` 直接报 `could not broadcast input array from shape (39,) into shape (47,)`，
10 个 episode 全部记为 `init_failure`（0 步、无视频），看似"0/10"实则完全无效。

**凡是在 Panda/ECO65 之间切换夹爪，都不能沿用 Panda 时代预计算的 `*.pruned_init` 初始状态。**
本仓库 `examples/libero/main.py:97-101` 的 ECO65 分支跳过 `set_init_state` 正是这个原因；
但该分支只判断机器人、不判断夹爪，**Panda + 非默认夹爪**会掉进这个坑。

判定一次评测是否有效，至少要检查：**每个 episode 的 steps > 0、视频文件数 = 2 × episode 数**。
