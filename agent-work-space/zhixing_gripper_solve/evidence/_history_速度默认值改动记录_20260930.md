## 2. 改动理由（实测，非推断）

同一 30 mm 试块、同一脚本专家链路（`outputs/expert_ZhixingGripper_w30_20260929_073109.json`
与 `outputs/_deprecated_harness_bugs/` 中的 speed=0.2 组）：

| speed | 闭合耗时 | 指垫穿透峰值 | 抬升 | 30 mm 试块结果 |
|---|---|---|---|---|
| 0.2（旧默认） | 2–5 个控制步（0.1–0.25 s） | 17.3 – 22.7 mm | 0 – 负值 | **0/15 全败** |
| 0.01（部署值） | 8–100 个控制步（0.4–5 s） | 0.03 – 3.2 mm | 74.0 – 75.0 mm | 可抬起，但投放/释放仍 0/4 |

`0.01` 也与 `PandaGripper` / `RethinkGripper` 的 `speed` 取值一致。
改动后**新资产默认即等于部署值**，不再依赖调用方记得注入环境变量。

## 3. 验证结果（改动后实测）

### 3.1 默认值确实生效（`outputs/diag/speed_asset_default.json`、`speeddirekt` 探针）

不设置任何环境变量、新建环境后：

```
gripper_class = ZhixingGripper
speed = 0.0100          来源：asset default
format_action 每次命令累积步长 = 0.01
累积到饱和所需步数 = 100
```

对照：显式 `ZHIXING_GRIPPER_SPEED=0.2` 时 `speed = 0.2000`、步长 0.2、
5 步饱和 —— 说明环境变量覆盖仍然有效。

### 3.2 用 N1 体检脚本自身复测（`outputs/diag/audit_new_default/`、`audit_old_env_0p2/`）

| 量 | 旧默认（env=0.2） | **新默认（不设 env）** | 与既有 N1 记录 |
|---|---|---|---|
| 开口行程 | 0.073493 m（73.49 mm） | **0.089654 m（89.65 mm）** | ✅ 与 `n1_reverify_20260928` 的 0.089654 m 逐位一致 |
| 全开 / 全闭 | 0.11258 / 0.03909 m | **0.11258 / 0.02293 m** | ✅ |
| 四连杆闭环最大残差 | **17.372 mm** | **9.084e-05 m（0.091 mm）** | ✅ 与既有 9.084e-05 m 一致 |
| 指垫自接触穿透 | **9.946e-05 m（0.0995 mm）** | **5.127e-07 m（0.0005 mm）** | ✅ 改善约 194 倍 |
| 极性 / 无 NaN | True / True | True / True | ✅ |

**结论**：改动后，任何**不设环境变量**的运行入口（N1 体检脚本等）从
"用 0.2 跑、残差 17 mm、自穿 0.1 mm"回到"用 0.01 跑、残差 0.09 mm"，
与既有 N1 复验记录重新对齐。

### 3.3 已知的口径残留（未在本次改动，如实登记）

`scripts/audit_gripper.py` 的两处默认文案与判定线仍写死旧值：

- 第 396 行 `speed_tag = os.environ.get("ZHIXING_GRIPPER_SPEED", "default(0.2)")`
- 第 432 行 `"default_speed": os.environ.get("ZHIXING_GRIPPER_SPEED", "0.2")`

因此新默认下运行，`timing.default_speed` 仍会被打印/写成 `0.2`，
而实测 `steps_to_full_close = 8`（对应 0.01）。**这是显示口径缺陷，不是行为缺陷**
（已用 §3.1 的直测确认真实 speed=0.01）。修改脚本属于另一处受管改动，
本次**未擅自改动**，留待用户决定。
