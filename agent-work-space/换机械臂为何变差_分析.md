# 为什么换成 ECO65 会变差？—— 本体无关接口 vs 分布内策略

| 项目 | 内容 |
| --- | --- |
| 日期 | 2026-09-26 |
| 决定 | **适配方案定为 ECO65 + PandaGripper**（下文第 1 节记录该决定及其代码影响） |
| 结论一句话 | π0.5 的**接口**是本体无关的，但**权重**是在"Panda 的视觉外观 + Panda 的动作后果"这一联合分布上拟合的；换机械臂同时改变了**输入分布**和**动作的物理后果**，闭环因此失效 |
| 关联文档 | `夹爪对照实验结论.md`（2×2 消融）、`docker_配置步骤.md`（部署） |

## 1. 决定：适配方案 = ECO65 + PandaGripper

依据：`夹爪对照实验结论.md` 的 2×2 显示知行夹爪本身就是充分致败因素（Panda 装上知行夹爪也从 10/10 掉到 0/10），
而 PandaGripper 是训练时的原始夹爪，语义与训练分布一致（注：各夹爪的 `format_action` 都是累加式，真正的差别是 speed 相差 20 倍，详见 `夹爪对照实验结论.md` 勘误）。

**代码改动清单**（把默认夹爪从知行换成 Panda）：

| 文件 | 改动 |
| --- | --- |
| `robosuite/models/robots/manipulators/eco65_robot.py` | `default_gripper` → `"PandaGripper"` |
| `third_party/libero/libero/libero/envs/robots/mounted_eco65.py` | 同上（LIBERO 桌面任务走的是 `MountedECO65`） |
| `examples/libero/main.py` | state 构造 `obs["robot0_gripper_qpos"][[1, 5]]` 是给 6 关节知行写的；PandaGripper 只有 2 个指关节，需改成 `[:2]`（否则 IndexError） |

注意：知行夹爪的代码与资产**不要删**——它仍是项目的适配成果之一，只是不进入默认评测路径。

## 2. 实测事实（全部来自本轮实验）

### 2.1 消融矩阵（`libero_spatial`，10 任务 × 1 次，seed 7，随机初始化）

| 机械臂 | 夹爪 | 成功率 |
| --- | --- | --- |
| Panda | PandaGripper | **10/10** |
| **ECO65** | **PandaGripper** | **0/10** |
| ECO65 | ZhixingGripper | 0/10 |
| Panda | ZhixingGripper | 0/10 |

→ 在**夹爪已经是训练配置**的前提下，只把机械臂从 Panda 换成 ECO65，成功率 10/10 → 0/10。

### 2.2 策略只吃图像（关键前提）

`pi05_libero` 的配置是 `Pi0Config(pi05=True, action_horizon=10, discrete_state_input=False)`
（`src/openpi/training/config.py:745`）。沿调用链：`TokenizePrompt` 不把状态数值交给 tokenizer；
`Pi0.embed_suffix` 只在 `not self.pi05` 时创建连续状态 token。

**结论：状态（含本体关节角、夹爪开度）数值不进入网络。策略的输出完全由两路图像 + 语言提示决定。**
→ 因此"换机械臂后行为变了"只可能来自**图像**的变化（不存在"状态通道泄露了本体信息"这种解释）。

### 2.3 量化对比（同一任务 task0、同 seed、同随机初始化、**同一夹爪**）

| 指标 | ECO65 + PandaGripper | Panda + PandaGripper |
| --- | --- | --- |
| 关节数 | **6（非冗余）** | **7（冗余）** |
| 机器人基座 | (-0.66, 0.0, 0.912) | (-0.66, 0.0, 0.912) ← **完全相同** |
| `init_qpos` | `[0, -0.3, -1.6, 0.3, 1.5, -1.5]` | `[0, -0.161, 0, -2.445, 0, 2.227, 0.785]` |
| t=10 时 eef 位姿 | (-0.165, 0.048, **1.086**) | (-0.209, 0.000, **1.173**) |
| eef 与起始的位姿差 | — | **z 方向低 8.7 cm** |
| `eye_in_hand` 相机（局部） | pos `0.05 0 0`, quat `0 0.7071 0.7071 0`, fovy 75 | **完全相同** |
| 关节限位利用率（0=下限,1=上限） | 0.22 ~ 0.78 | 0.21 ~ 0.67 |
| 是否撞限位 | 否（near-limit 占比 0） | 否 |
| t=10 时到最近物体距离 | **0.185 m**（更近） | 0.285 m |
| 末端总位移 | 0.269 m | 0.275 m |
| 动作幅度 \|a\| 均值 | 0.224 | 0.208 |
| 画面平均像素差（agentview） | 11.35 / 255（4.5%） | ← 两列之差 |
| 画面平均像素差（wrist） | **28.58 / 255（11.2%）** | ← 两列之差 |

**由实测可以排除的原因：**

| 假设 | 证据 | 结论 |
| --- | --- | --- |
| "够不到物体" | ECO65 到最近物体 0.185 m，比 Panda 的 0.285 m 更近 | ❌ 排除 |
| "撞关节限位" | 两机限位利用率都在中段，near-limit 占比 0 | ❌ 排除 |
| "策略对 ECO65 输出乱码" | 末端位移、动作幅度与 Panda 同量级，轨迹朝向桌面 | ❌ 排除 |
| "基座位置/安装方式不同" | 两者 `robot_pos` 完全相同 | ❌ 排除 |
| "腕部相机参数被改坏了" | 两机 `eye_in_hand` 局部 pos/quat/fovy 完全一致 | ❌ 排除 |
| "夹爪" | 本对照里夹爪相同；且 Panda+知行 单独也 0/10 | ❌ 排除（对 B 格而言） |

## 3. 逐层分析：为什么"不绑定机械臂"只在接口层成立

### 3.1 接口层：确实是本体无关的

π0.5 的 I/O 协议是通用的：

```text
输入:  两路 RGB 图像 + 语言提示 (+ 状态，本配置下不参与条件)
输出:  action_horizon × 7 = [dx, dy, dz, d_rx, d_ry, d_rz, gripper]  （末端位姿增量 + 夹爪标量）
```

这套接口对任何"末端位姿 + 1 自由度夹爪"的机械臂都成立，ECO65 和 Panda 都满足（两者都是 OSC_POSE、action_dim=7）。

### 3.2 分布层：权重拟合的是"Panda 观测 → Panda 动作"的联合分布

策略实际学到的是 `π(a | o)`。换机械臂时：

```text
   o  = g_robot(物理状态)     ← 观测函数变了（画面里手臂不同、腕部高度不同）
   a  → f_robot(a, 状态)      ← 动作的物理后果变了（同样的 eef 增量到达的位姿不同）
```

两者**同时**变化，而闭环控制依赖"我发出 a → 我看到 o' → 我判断 a 是否奏效"。
一旦 `g` 变了，策略就无法正确评估自己的动作效果；一旦 `f` 变了，它的开环计划也不成立。

**本轮最直接的证据**（见 `夹爪对照实验结论.md` §3.1）：
只把夹爪换成知行（**唯一变化是腕部画面里的夹爪外观**），策略的夹爪指令序列就从
"-1 保持张开 → 到位后 +1 闭合" 变成 "**+1 全程闭合**"。状态不参与条件，所以这个变化只能来自图像
——**同一张桌子、同一个碗、同一句指令，仅因为画面里的机械末端长得不一样，策略的行为就完全不同。**

### 3.3 具体到 ECO65，四个已量化的分布偏移

**(1) 第三人称视角（agentview）里的手臂外观**
两机基座相同、场景相同，画面平均像素差 4.5%，差异集中在**手臂本体**：
ECO65 是细长银色 6 轴臂，Panda 是粗壮白色 7 轴臂，且姿态完全不同（ECO65 肘部深度折叠）。

**(2) 腕部视角（wrist）的尺度**
同一帧（task0/seed7/第 20 帧）对比：ECO65 的腕部相机看到的物体**大约大一倍** —— 因为它的 eef 比 Panda 低约 9~13 cm，
相机离桌面更近。物体在画面里的尺度是策略判断"离物体还有多远"的主要线索，尺度变了 → 距离判断失准
（这解释了为什么它会更早/更猛地往下压）。

> 注意：两机 `eye_in_hand` 的**局部**参数完全一致，且相机与 `grip_site` 的相对位姿在两机上也是同一个
> （都通过同一个 PandaGripper 变换链）。所以腕部画面的差异**不是相机装错了**，而是**末端位姿不同**导致的。

**(3) 末端起始位姿差 8.7 cm**
`MountedECO65.init_qpos = [0, -0.3, -1.6, 0.3, 1.5, -1.5]` 是适配时人为选的，与 Panda 的
`[0, -0.161, 0, -2.445, 0, 2.227, 0.785]` 没有任何对应关系。实测起始 eef 高度差 **8.7 cm**，
而策略的第一个动作块是在 Panda 起始位姿附近学出来的。

**(4) 非冗余 vs 冗余（6-DOF vs 7-DOF）**
- Panda 有 7 个关节 → 给定末端位姿存在 1 维零空间自运动，OSC 天然能保持自然姿态、绕开限位；
- ECO65 只有 6 个关节 → 末端位姿唯一确定关节角，靠近工作空间边界时姿态会剧烈变化。

仓库作者已经意识到这一点：`robosuite/robots/single_arm.py:252-259` 专门加了针对**非冗余**机械臂的关节 PD 回拉，
注释原文：*"Joint PD to resist posture drift on non-redundant robots. This small spring pulls each joint toward
init_qpos, mimicking the nullspace stabilization that redundant robots get natively."*

但这个 PD 项是"把关节往 `init_qpos` 拉"，当任务需要偏离初始姿态时它**与 OSC 的任务空间控制对抗**，
会带来稳态误差；而且它把机械臂往一个**策略没见过的**姿态上拉。

**(5) 力矩上限差异（静态）**
ECO65：`±60, ±60, ±30, ±10, ±10, ±10` N·m；Panda：`±80, ±80, ±80, ±80, ±80, ±12, ±12` N·m。
ECO65 的 3~6 轴明显更弱，高速/大姿态偏差时更容易被限幅。

## 4. 因果链（当前的最佳解释）

```text
MountedECO65.init_qpos 是人为选的（与 Panda 无对应）
        │
        ├─→ 起始末端位姿低 8.7 cm ──→ 腕部相机离桌更近 ──→ 画面里物体尺度失真
        │                                                   └→ 策略误判高度/距离
        │
        ├─→ 手臂外观、姿态与训练分布不同 ──→ agentview 输入 OOD
        │
        └─→ 6-DOF 非冗余 + 关节 PD 回拉 ──→ 姿态被拉扯、稳态误差
                        │
                        ▼
        策略输出的动作块（尤其下降时机与夹爪时序）按 Panda 几何规划
                        │
                        ▼
        在 ECO65 上抓空 / 撞到盘子 → 0/10
```

**证据强度说明**：
- 「状态不进网络、行为差异只能来自图像」——**已由代码与实验证明**（§2.2、§3.2）。
- 「起始位姿差 8.7 cm、腕部尺度差约 2×、限位未饱和、可达性更近」——**实测数字**（§2.3）。
- 「起始位姿差 → 尺度失真 → 策略误判」这条因果链的中间环节是**推断**，尚未用对照实验证明
  （验证方法见 §5 第 2 项）。
- 「关节 PD 回拉造成稳态误差」也是**推断**：注意 Panda 同样吃了这项仍然 10/10，所以它不是主因。

## 5. 建议的下一步（按性价比排序）

| 优先级 | 实验 | 目的 / 预期 |
| --- | --- | --- |
| ★★★ | **对齐初始位姿**：用 IK 反解出「使 eef 起始位姿等于 Panda 起始 eef 位姿」的 ECO65 关节角，替换 `MountedECO65.init_qpos`（以及 `ECO65.init_qpos`） | 最便宜、最可能显著改善；同时验证 §4 的因果链 |
| ★★☆ | **对齐腕部视角**：把 `ECO65-B/robot.xml` 的 `right_hand` 位姿改成与 Panda 一致（`pos="0 0 0.1065"`，绕 z −45°），或直接调 `eye_in_hand` 的 pos/fovy，使同一 eef 高度下物体在画面中的尺度与 Panda 一致 | 验证"尺度失真"假设 |
| ★★☆ | **关掉关节 PD 项做对照**（`single_arm.py:252-259` 做成开关） | 量化它对跟踪/成功率的影响 |
| ★★☆ | **`init_qpos` 与 `right_hand` 两项都对齐后再跑 4 格矩阵** | 判断"只对齐几何能否救回一部分成功率" |
| ★★★ | **用 ECO65 + PandaGripper 自己的数据微调**（复现方案 M5） | 根本解；前四项只是把分布偏移变小，不能消除 |

**汇报口径建议**：当前 0/10 的结论应写成
"在**未做任何分布对齐**、直接用 Panda 权重驱动 ECO65 的条件下为 0%"，并注明成功率对比来自每格 10 个 episode。
