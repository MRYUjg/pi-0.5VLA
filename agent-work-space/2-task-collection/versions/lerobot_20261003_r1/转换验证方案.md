# LeRobot转换验证方案

版本lerobot_20261003_r1，2026-10-03。用户明确本轮只做转换验证，不做训练。工作在CPU独立环境完成，原采集与覆盖冻结版本不变。

输入固定为coverage_train_val_r1已接受的12条HDF5，按原清单分为train 9条和validation 3条。旧pilot与保留test不混入。转换前后核对原始数据、审计、回放及清单哈希；不接受失败、重复、跨划分或内容漂移的源数据。

使用仓库pyproject.toml锁定的LeRobot提交0cf864870cf29f4738d3ade893e6fd13fbd7cdb5，其公开Dataset API生成v2.1数据。独立运行时仅安装数据读取/转换依赖及CPU PyTorch；不安装完整机器人/策略训练依赖，不加载模型权重，不上传Hub。

## 数据契约

| 输出 | 原始数据与处理 |
|---|---|
| image / wrist_image | observations对应RGB，256×256×3，保持已有朝向，无损PNG内嵌Parquet；不再翻转/裁剪/缩放 |
| state | observations/state的前T个值，float32、8维，TCP位置/轴角及具名左右夹爪关节 |
| actions | transitions/actions，7维，float64转float32；不改变归一化OSC含义，不额外做delta/裁剪/反转夹爪 |
| task | 原语言描述，通过LeRobot task_index关联 |
| timestamp | episode内i/20秒，起点0；原始仿真起始时间保存在provenance |
| next.done | 仅最后一个记录动作为true，不使用可能提前触发的环境done截断 |
| episode/frame/index | 由LeRobot生成，逐条对应源seed、scene和帧区间 |

每条源HDF5有T动作、T+1观测；仅(o_t,a_t)组成T个训练行，末端o_T不虚配动作，仍完整保存在原文件。120步准备动作不导出。train和validation输出为独立本地repo_id，分别计算LeRobot元数据统计；验证统计不混入训练统计。本轮不生成OpenPI训练归一化资产，不运行训练。

## 验证门槛

先各选第一条train和validation执行小规模转换及全帧读取，再执行正式全12条转换。每次使用唯一新目录，不覆盖失败产物；运行日志、版本哈希及真实退出码保留。

1. 官方LeRobotDataset重新加载数据，全量检查计数、20Hz时间、索引、语言、state、actions、next.done和双相机像素。
2. float64转float32动作误差单独报告，转换后数值必须严格等于原值的float32表示；图像无损，逐像素相等。
3. 50步动作块在每条起点、中段、尾部检查，末端只重复本episode最后动作并标记actions_is_pad，不跨episode。
4. CPU PyTorch DataLoader读取batch，检查双图像、state、action chunk及mask维度。
5. train/validation数值统计分别与对应源帧独立重算比对，检查计数及划分无泄漏。
6. 用真实读取帧构造动作/状态/图像/时间/末端标记/语言错误，确认验证函数拒绝；源记录检查拒绝未通过、重复、test误入train。
7. 检查已有输出拒绝覆盖、原采集冻结指纹及HDF5转换前后哈希不变。

OpenPI键名和维度对齐仓库LIBERO接口；本轮验收针对LeRobot公开读取器和CPU批加载，不声称已执行完整OpenPI模型预处理、训练或闭环推理。
