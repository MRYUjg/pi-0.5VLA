## 1. 审核结论

返工有实质进展，但“R1–R6 全部闭环、N4 已通过、R7 方法论已关闭”的结论仍偏强。目前不宜把这批数据作为已验收训练数据，也不宜进入规模采集与正式微调。

本次最重要的两个发现：

1. **N4 存在实际可复现的误放行**：在内存中破坏后半段动作并错移腕部图像，实际回放任务失败，当前逐条审计函数仍输出 `pass=true`。
2. **N3 旋转失败存在可修复的控制器因素**：关闭 OSC 输出之外额外叠加的初始关节位姿 PD 后，独立空载测试中 `+ry` 误差从 2.257° 降为 0.212°，±90° 重定向均收敛。因此不能据现有失败认定 ECO65 固有旋转能力不足，或直接期待微调解决。

|---|---|---|

## 2. P1：N4 的 PASS 仍不能证明完整轨迹可回放

### 2.1 代码与结果证据

`scripts/n4_audit.py:44–49,438–489` 虽然执行全段动作回放，却只把第 20–44 帧的机械臂/夹爪误差接入硬判据；渲染核对仅覆盖前段若干帧的 `agentview_image`。全程物体位置/姿态偏差仅记录，腕部相机没有对应回放核对，也未要求回放末端原生成功谓词为真。

现有 `results/n4v5_audit.json` 五条数据全部 PASS，但全程最大偏差如下：

|---|---:|---:|---:|---:|
| 2 | 0.0263 | 0.0395 | 139.50 | 1.586 |
| 3 | 0.0358 | 0.0755 | 28.91 | 0.137 |
| 4 | 0.5680 | 0.6525 | 575.24 | 2.993 |
| 5 | 0.0187 | 0.0371 | 23.35 | 0.347 |
| 6 | 0.0230 | 0.0376 | 9.61 | 0.236 |

这些数值证明“全程回放超阈值会硬失败”的描述不成立。现有审计未记录原始五条回放的最终成功状态，因此这里不把它们一概判为任务失败；应标为**完整回放验收未证明通过**。

本次独立负对照针对 seed 4：

- 原 NPZ 不变，只在内存中将 `actions[100:, :6]` 置零、夹爪改为张开；腕部图像循环错移 1 帧。
- 调用当前 `check_episode(..., replay=True)`；其全部逐条检查均为真，`pass=true`。
- 实际回放末端原生成功谓词为假；机械臂误差达 0.687 rad，物体位置误差达 191.05 mm。
- 此试验同时注入两种错误，证明当前逐条验收会放行坏样本；下一版应拆成独立负对照，逐一验证检测能力。本次没有把全局自检重复算入单条试验。

证据：`rework_review_20260928/audit_negative_control.json`、`probe_audit_negative.py` 及日志。

### 2.2 判别力自检也有逻辑缺口

`scripts/n4_audit.py:193–194` 用 `max(err(+1), err(-1))` 与正确配对比较。这样只需一个错位方向较差，就可能通过；不能证明两个错位方向都比正确配对差。

当前结果是：正确配对 0.128，+1 帧 0.258，−1 帧 0.309；三者都小于正式图像验收阈值 3.0。自检表明本段正确配对误差较小，却没有证明正式验收会拒绝错位数据。

### 2.3 修改措施与验收

1. 用 episode 元数据构建对应 suite/task/机器人/夹爪环境，取消固定 `libero_object/task 0` 的回放假设。启动时核验资产、控制器、速度及相机配置指纹。
2. 查清首个分歧帧：保存并恢复模型相关初态、积分器状态、执行器控制量、夹爪累积命令及控制器目标/内部状态。对比单步 action、实际 ctrl、qpos/qvel、接触和目标误差，定位首次偏离。现阶段不能仅凭“接触敏感”解释数百毫米偏差。
3. 将接近、闭合、抬升、搬运、释放、撤离的全程误差接入判据；同时要求回放最终原生成功、释放后稳定、无异常/非有限值。允许数值容差，但须基于同配置重复运行标定，并在最终放行前固定。
4. 两个相机均核对首帧、关键动作前后、末帧与运动窗口。结合机器人/物体区域指标和几何状态，避免背景像素稀释错位信号。
5. 自检改为两个偏移都需被区分，并对**同一个正式验收入口**分别注入动作错位、尾段动作替换、腕部图像错位、物体状态破坏；每种负对照都必须 FAIL，正确样本必须 PASS。仅改 `max` 为 `min` 还不够。
6. `--no-replay` 只输出“静态检查通过”，不能使用完整数据验收的 PASS。

完成标准：修复后重新采集至少 5 条不同初始化成功轨迹，逐条完整回放达标，所有负对照被拒绝。现有轨迹保留为诊断证据，暂不列入已验收训练集。

## 3. P1：额外关节 PD 正在干扰 OSC，应先修控制器再归因模型

### 3.1 原因与独立消融

项目文件 `/mnt/data/vla-policy/openpi/robosuite/robots/single_arm.py` 在 `controller.run_controller()` 之后额外叠加：

```python
joint_kp = 3.0
joint_kv = 2 * sqrt(joint_kp)
torques += joint_kp * (init_qpos - qpos) - joint_kv * qvel
```

该项直接把关节拉回初始角度，未经过任务零空间投影。目标姿态需要明显偏离初始关节角时，它会与末端控制目标竞争。该逻辑位于共用 SingleArm 类，不能直接全局删除后沿用历史 Panda 对照。

本次在独立进程中修改内存方法，将上述 `joint_kp` 设为 0，连带取消该额外阻尼，未改生产文件；复用当前 N3 伺服例程，使用同一 Object task 0 环境/seed、`speed=0.01`，空载测试后再保持 10 步取误差：

| 设置 | 动作 | 收敛 | 位置误差 / mm | 姿态误差 / ° |
|---|---|---|---:|---:|
| 原额外 PD，位置/姿态解耦 | +ry 0.15 rad | 否 | 3.880 | 2.257 |
| 关闭额外 PD，保持解耦 | +ry 0.15 rad | 是 | 3.181 | 0.212 |
| 原额外 PD，保持解耦 | 工具 z +90° | 否 | 2.399 | 3.959 |
| 关闭额外 PD，保持解耦 | 工具 z +90° | 是 | 0.302 | 0.241 |
| 原额外 PD，保持解耦 | 工具 z −90° | 否 | 2.391 | 3.912 |
| 关闭额外 PD，保持解耦 | 工具 z −90° | 是 | 0.441 | 0.240 |

另测“关闭额外 PD + 6D 耦合 OSC”：三项均收敛，位置误差分别约 0.282/0.031/0.031 mm，姿态误差约 0.265/0.240/0.240°。它是候选配置，不应只凭三个点就定为最终配置。

证据：`rework_review_20260928/control_probe.json`、`probe_control.py` 及日志。共 3 配置 × 3 动作；探针图像为占位数组，不参与视觉评价。这里验证的是空载控制机制，**没有完成带载重定向、原 N3 全矩阵或策略成功率复验**，不能把原来的 2/6 改写为已通过。

### 3.2 修改措施与验收

1. 将额外关节回拉项配置化，先建立 ECO65 候选配置，关闭这项额外 PD，保留控制器自身补偿机制；保持 Panda 原配置作为对照。不要先加大所有增益或放宽角度阈值。
2. 先以其余设置不变的候选完成平移/旋转复验，再独立比较 6D 耦合方案；同时记录力矩饱和、关节限位、雅可比条件、碰撞及夹爪约束残差。
3. 修正收敛判断时序：控制步执行后重新读位姿；保持窗口结束后同时检查位置和角度，避免使用上一步误差或只检查旋转。
4. 将接近、重定向、下降阶段未收敛接入失败/重规划分支。当前流程可在重定向未收敛后继续抓取，抓取成功不能替代姿态要求通过。
5. 在同一最终代码/参数版本下重跑 12 个跟踪探针、3 组宽度各 10 次抓放、6 次重定向抓取，再用另一组独立 seed 复验；保留既有阈值，不只重跑失败项。

此外，`results/n3_osc_full_chain.json.run_segments` 明确记录：宽度结果来自旋转限幅有误的 v1，旋转/重定向来自修正后的 v2。阈值不变不等于算法不变。当前可以报告各次实验结果，但不能用拼接结果证明一个统一部署版本完成验证。

## 5. P1：夹爪速度与动态验证尚未贯穿部署入口

### 5.1 局部速度设置不能代表部署配置

N3/N4 显式使用 `speed=0.01`，但当前 ZhixingGripper 类默认仍为 0.2；本次地面环境实例化也实际读到 0.2。未显式覆盖参数的评测/部署入口仍可能使用这一默认值。

N1 的 speed=0.2 消融中，最终 tip 间距约 39.09 mm；speed=0.01 下约 22.93 mm。若“闭合收敛时间”只按最终实际停留位置计算，卡在错误开口也会被算作迅速收敛。应比较**指定目标**、速度与约束残差，不能只比较是否停下。

统一定义物理开口：tip site 间距、指垫中心间距、指垫内表面净开口不是同一个量。N1/N2 数字不能直接混用为最大可抓宽度；契约应分别命名并以指垫内表面开口描述容纳尺寸。

### 5.2 N2 的“部署路径斜坡”实际是受控几何试验

`scripts/n2v2_settled_probe.py:220–258` 自行插值写执行器 ctrl，并在每个子步锁定机械臂 qpos/qvel。斜坡从归一化中点开始，不是从真实的上一帧夹爪累积命令开始。因此可支持“此斜坡几何试验能收敛”，不能单独证明完整 `env.step → format_action → actuator` 路径稳定。

记录已发现阶跃输入会造成关节越界和明显约束残差。这是重要发现，但“只有瞬时满量程闭合会卡死、采集/回放链路安全”的范围超出了现有测试。

措施：

- 用一个配置/环境工厂贯穿采集、回放、策略评测；保存运行时真实参数与哈希并断言一致。速度应与物理时间关联，避免物理子步改变后等效速度变化。
- 沿真实 env.step 路径验证开→合→开、半程反向、reset 后立即闭合、空载/带载及不同臂姿态；不能只用直接写 ctrl 的探针替代。
- 在控制接口限速，并使 reset 时累积命令与真实夹爪状态一致；加入关节范围、equality/connect 残差、接触穿透及超时失败检查。
- 若受控慢速动作仍导致约束异常，再针对质量惯量、阻尼、armature 和约束参数做单变量实验，不宜直接把所有约束调硬。

完成标准：所有正式入口读取同一冻结配置；上述动作序列均达到声明目标开口/夹持状态且约束指标达标，再认定动态部署路径通过。

## 6. P1：成功判定与教师超时需要一起修正

`scripts/n4_collect.py:788–822` 存在三个不足：

1. `success = ep.done and in_basket` 没有包含后面计算的 `post_release.stable`，可把稳定性不足的轨迹先存为 success。
2. stable 只要求观察计数大于 0、最终谓词/位置成立及起终点漂移较小，没有要求完整 40+30 步、连续窗口成立或最大窗口漂移/低速度。
3. `predicate_true_at_release` 在整段观察结束后才赋值，实际不是释放时刻的值；审计又直接信任元数据中的 stable。

措施：分别记录释放瞬间、沉降结束、观察窗口的状态；稳定窗口要求持续满足谓词/区域条件、最大位移与速度限制。将稳定性纳入正式保存/验收的成功门槛，并在回放中重新计算。缺步骤或中途异常不能以最终一个成功点放行。

最新 n4v5 成功轨迹实际为 **517、521、521、523、529 帧**。五条的 transport 均耗满 220 步，place 均耗满 160 步，约 73% 帧数花在这两段未达到位置容差的伺服上。该问题已在最新验收协议 JSON 中指出，值得保留；它不是单纯“任务需要很长”。

建议先对带载 transport/place 做上一节控制器消融，记录稳态位置/角度误差、目标可达性及夹持滑移，区分额外 PD、增益、姿态约束与目标点因素。检查 `servo()` 返回值，超时必须触发失败或有记录的重规划。根据任务约束设计可达释放区域；不要只缩短等待、增大 MAX_STEPS 或放松成功条件。

可把完成任务时间与成功后的诊断观察时间分开记录，但不能靠删除 70 步观察掩盖前面 380 步未收敛。当前演示仍未证明能在目标评测时限内完成。
