## 0. 摘要（先看这一节）

1. **N0 完成指纹冻结。** 9 类关键源码 sha256、5 个回退备份、镜像/依赖/GPU 环境全部入库；`default_gripper` 的文档冲突已裁定（见 1.2）。
2. **基线不可精确复现。** 同配置、同 seed、同代码，ECO65+PandaGripper 重复 4 次得到 **9 / 8 / 9 / 10**（满分 10）。根因是 π0.5 推理侧的**有状态 RNG**，不是配置差异。**推论：10 episode 的单次结果差 1 个 episode 属于纯噪声，不能作为 A/B 结论。**
3. **N1 发现 ZhiXing 的夹爪极性是反的。** `action=+1` 实际**张开**（11.26 cm），`action=-1` 实际**闭合**（2.28 cm）；Panda 基准恰好相反（+1=闭合 0.10 cm）。这与代码 docstring、XML 注释**同时矛盾**。
4. **N1 发现 `init_qpos` 严重不自洽。** 声明值 `[-0.91]` 被广播到 6 个关节，导致 4 个关节符号错、**最大 equality 残差 1.82 rad**、**左侧四连杆 connect 残差 34.73 mm**。自洽 6 元素初始化可把两者都降到 **0.0**。
5. **两个缺陷已修（默认关闭的进程内开关），但都不足以恢复 ZhiXing：0/10 → 0/10。** 这是**实测负结果**（环境变量已确认透传进容器）。说明 0/10 的**主导阻塞仍在策略侧的视觉 OOD**——与方案 P3 的判断一致，自数据微调/视觉对齐仍是必经之路。
6. **但这两个修复是 P1 的前置条件。** 若带着反转极性去采集示范并训练，数据与策略会**继承错误的夹爪约定**，后期极难排查。这正是 P0 体检的价值所在。
7. **N3 必须带着修复开关运行**，否则测的是 bug，不是夹爪。

### 1.5 不可复现的根因（已定位到源码行）

```python
# src/openpi/policies/policy.py:65
self._rng = rng or jax.random.key(0)
# :75 每次 infer 都分裂并推进
self._rng, sample_rng_or_pytorch_device = jax.random.split(self._rng)
```

`src/openpi/models/pi0.py:192-197` 用该 rng 采样 flow-matching 的**噪声**与**积分时间步**（`jax.random.normal` / `jax.random.beta`）。RNG 状态随服务进程的**请求历史**推进，因此：

- 同样的评测，若服务进程不同（或此前已服务过其他请求），采样噪声就不同 → 动作不同 → 结果差 1~2 个 episode；
- 时间线佐证：`H` 跑于 **07:49:25 UTC**，而当前服务进程 **08:35:11 UTC** 才启动 → **不同实例**。

## 2. N1 执行结果

### 2.1 结构

| 项 | 值 |
|---|---|
| 夹爪类 | `ZhixingGripper`，`dof=1`，**6 个联动关节** |
| gripper_qpos 索引 | `[6, 7, 8, 9, 10, 11]`（关节声明序：Left_1 / Left_Support / Left_2 / Right_2 / Right_1 / Right_Support） |
| actuator | `gripper0_gripper`，`ctrlrange=[-0.91, 0]`，`kp=100` |
| 约束 | 5 条 joint equality + 2 条 connect（左右四连杆闭合） |
| 动作映射 | `ctrl = bias + weight·current_action`，`bias=-0.455`、`weight=0.455` |

### 2.2 缺陷一：`init_qpos` 单值广播 → 严重不自洽（实锤）

`zhixing_gripper.py` 的 `init_qpos` 返回 **1 个元素** `[-0.91]`，而 `robosuite/robots/single_arm.py:181` 把它赋给 **6 个**关节索引 → numpy 广播：

| 初始化方式 | reset 后 6 关节 qpos | 最大 joint equality 残差 | 左侧四连杆 connect 残差 |
|---|---|---|---|
| **声明式（现状）** | `[-0.91] ×6` | **1.82 rad**（≈104°） | **34.73 mm** |
| **自洽 6 元素** | `[-0.91, 0.91, -0.91, 0.91, 0.91, 0.91]` | **0.0** | **0.0** |

逐条残差（声明式）：`eq_Left_2 = 0.0`、`eq_Right_1 = eq_Right_2 = eq_Left_Support = eq_Right_Support = -1.82 rad`。
即 4 个从动关节的符号全错，且**左侧四连杆在 reset 瞬间就张开 3.5 cm**，必须靠求解器强行拉回。

### 2.3 缺陷二：开合极性**反转**（双路径交叉验证）

**路径 B（真实动作链路，`env.step` 7 维动作）**

| 夹爪 | `action=-1` | `action=+1` | 判定 |
|---|---|---|---|
| **ZhiXing** | ctrl `[-0.91]` → 开口 **2.28 cm**（近闭） | ctrl `[0.0]` → 开口 **11.26 cm**（全开） | **+1=张开** ❌ |
| **PandaGripper**（同机器人同协议，基准） | ctrl `[0.04, -0.04]` → 开口 **7.94 cm**（开） | ctrl `[0.0, 0.0]` → 开口 **0.10 cm**（闭） | **+1=闭合** ✅ |

**路径 A（直接写 `sim.data.ctrl` 扫全量程，独立口径）**：单调递增

```text
ctrl  -0.9100 → jaw 0.02970 m      ctrl  -0.4550 → jaw 0.08468 m      ctrl  -0.0758 → jaw 0.10547 m
ctrl  -0.7583 → jaw 0.05178 m      ctrl  -0.2275 → jaw 0.09093 m      ctrl   0.0000 → jaw 0.11300 m
```

**结论**：ZhiXing 的 `action → ctrl → 开口` 语义与 **Panda/LIBERO 约定（+1=闭合）相反**，也与本文件 docstring 的 `-1 => open, 1 => close` 及 `init_qpos` 注释 `-0.91 = fully open` **同时矛盾**。脚本判定 `zhixing_polarity_inverted_vs_panda: True`。

> 这条修正了一个流传中的结论：既有文档把「策略全程输出 +1」解释为「**过早闭合**」。按实测，+1 实际是**张开**——真实情况是「**全程张开，从未闭合**」。两种叙述都指向抓空，但机理与修复方向完全不同。

**解读**：
- 两个缺陷**是真的**，且已修好；但它们**不是** 0/10 的主导原因。
- 真正的主导因素在**策略侧**：π0.5 装上 ZhiXing 后**不产生抓取时序转换**（夹爪指令无 `-1 → +1` 的到位闭合动作）。极性无论正反都抓不到 —— 正着是「全程张开」，反着是「全程闭合」。
- 因此 **自数据微调 / 视觉对齐仍是必经之路**，与方案 P3 一致。
- **但**：若不修极性就进入 P1，采集到的示范会编码**错误的夹爪约定**（把「张开」标成 +1），训练出的策略与标准约定不兼容，后期极难定位。**这两个修复是 P1 的前置条件。**
