## 0. 摘要（先看这一节）

1. **PandaGripper 的对齐结论对 ZhiXing 不成立。** ECO65+PandaGripper 与 Panda+PandaGripper 的 `T_cam2grip` 逐位相同（差 `2.2e-13` mm），这正是当初「对齐成立」的依据；但装上 ZhiXing 后平移差 **23.000 mm**、旋转差 0.0°。23 mm = `0.120 − 0.097`，即两者 `eef` 安装长度之差。

2. **新发现：ZhiXing 的 `grip_site` 不在夹持区，而在手指根部。**
   - PandaGripper：夹持点（两指垫**内侧面中点**）在 `grip_site` 沿接近轴 **−3.60 mm**，且**与开合无关**（平动指，实测恒定）；指尖最深 **+9.30 mm**。符合「命令点到即可夹」的语义。
   - ZhiXing：夹持点在 **+82.54 mm（闭合）～ +65.11 mm（全开）**，**行程内沿接近轴前移 17.44 mm**；指尖最深 **+102.45 mm**。
   - 后果：**当前落地 `init_qpos` 下，ZhiXing 的夹持点比 Panda 的夹持点低 109.16 mm。**
   - **该结论口径无关**：按「指尖最深顶点」对齐差 93.15 mm，按「夹持点」对齐差 109.16 mm，量级一致。

3. **这不是「初始位姿」问题，而是「整条轨迹」问题。** 策略的动作作用于 `grip_site`；`grip_site` 落在手指根部，意味着**整条轨迹的夹持点都被系统性偏移 65～83 mm**。因此只重解初始位姿**不足以**修复——必须修 TCP 定义本身（见 §4.1）。

4. **初始位姿已重解并通过判据**：候选 `init_qpos` 使 **ZhiXing 的夹持点**落在 Panda 的夹持点位置（由参考 `grip_site` 位姿推出），残差 **0.0007 mm / 0.00001°**，最小关节余量 **1.5424 rad**（优于当前 1.310 rad）。**未落地**。

5. **腕部视觉占比：ZhiXing 约为 Panda 的 1.36～1.46 倍**（25.05% vs 18.49% @reset）。用一阶近似，对齐需相机后移 **32～40 mm** 或 `fovy` 75°→**83.5～85.6°**。**但 `eye_in_hand` 为 Panda 与 ZhiXing 两条路径共用**，直接改会污染 9/10 基线 → 必须按夹爪条件化，列为**低优先级**（见 §4.3）。

6. **证据链自校验通过**：测量用 `local_z = right_gripper_z − 0.120` 反算出 XML 声明的 `Left_1_Link` 位置为 **−15.85 mm**，与 XML 的 `0.10415 m` **精确吻合**。说明单位（m）、坐标变换与 mesh 顶点读取都正确，该发现不是量纲或变换错误。

## 1. 测量口径与验证链

### 1.1 口径定义（避免歧义）

| 术语 | 定义 |
|---|---|
| `grip_site` | robosuite/OSC 使用的 eef site；**策略动作即作用于此点** |
| 接近轴 | `grip_site` 局部 **+z**（指向桌面下方）。由 `ee_z` 标记 site（+100 mm）与 Panda 手指朝向双向确认 |
| 夹持点 | 两指垫碰撞 geom **内侧面中点**（沿闭合轴取最靠前一薄层顶点的质心） |
| 前伸量 | 沿接近轴相对 `grip_site` 的位移，**正值 = 更深入工作空间（更低）** |

### 1.2 为什么不能用「最近点对」

ZhiXing 是**二连平行连杆**：实测两指垫内侧面法向夹角在整个行程内仅 **2.71°～3.22°**，即两面**始终接近平行**（Panda 为 **0.00°**）。

**平行的两个平面之间，最近点对是退化的** —— 任意点对距离都接近最小值，取 `argmin` 会跳到网格角点。实测同一位形：

| 口径 | 闭合位夹持点前伸量 |
|---|---:|
| 最近点对中点（**作废**） | +66.03 mm |
| 内侧面中点（**采用**） | **+82.54 mm** |

差 16.5 mm，**该差异不是噪声而是系统性低估**。这是本节点唯一一次自我纠错，记录在此以免后人重复。

### 1.3 三条独立验证

1. **量纲与变换自校验**：ZhiXing `grip_site` 局部系中 `Left_1_Link` body 位于 **−15.85 mm**；XML 声明 `right_gripper` z=**0.10415 m**、`eef` z=**0.120 m**，`0.10415−0.120 = −0.01585` **精确吻合**。
2. **约束收敛校验**：所有开合位形都通过**驱动执行器 + `mj_step`**得到（`mj_kinematics` 不强制 `connect` 约束，会把「连杆未闭合」误读成几何形变）。闭合位残差：joint equality **0.00e+00**、connect **5.25e-05 m**。
3. **两个独立指标一致**：夹持点前移量 17.44 mm（内面口径）与 `Left_Support_Link` body 原点前移量 17.44 mm（刚体原点口径）**完全一致**。
4. **与既有失败现象吻合**：既有记录 `G_eco65_zhixing_contactfix__agentview__f219.png` 显示「夹爪压在盘子上、把餐具撞翻、始终没夹住碗」——正是「手指比预期深 65～93 mm」应有的现象。

## 2. 实测结果

### 2.1 TCP / 指尖几何对照

| 指标（沿接近轴，相对 `grip_site`） | PandaGripper | ZhiXing | 差值 |
|---|---:|---:|---:|
| 指尖最深顶点（**口径无关，最稳**） | **+9.30 mm** | **+102.45 mm**（闭合）/ **+85.02 mm**（全开） | **+75.7 ～ +93.2 mm** |
| 夹持点（内侧面中点）@闭合 | **−3.60 mm** | **+82.54 mm** | **+86.14 mm** |
| 夹持点 @全开 | −3.60 mm | +65.11 mm | +68.71 mm |
| 夹持点行程内沿接近轴位移 | **0.00 mm**（平动指） | **17.44 mm** | — |
| 两指垫内面法向夹角 | **0.00°** | **2.71°～3.22°** | 两者均接近平行 |
| 内面间距（闭 / 开） | 0.00 / 78.19 mm | 0.52 / 89.96 mm | — |
| 法兰（`ft_frame`） | −97.00 mm | −120.00 mm | 23.0 mm |
| `eef` 安装长度 | 0.097 m | 0.120 m | 23.0 mm |

**结构解释**：ZhiXing 的 `grip_site`（`eef` 在 `0 0 0.12`）恰好落在**两个手指连杆根部之间**（`Left_1_Link` −15.85 mm、`Left_2_Link` +1.00 mm），而手指向前伸到 +102 mm。PandaGripper 的 `grip_site`（`0 0 0.097`）则落在**指垫高度**（夹持点 −3.6 mm、指尖 +9.3 mm）。两者 TCP 约定**根本不同**。

**平行连杆的额外含义**：ZhiXing 两指垫保持平行（≈3°，符合平行连杆特征），但**夹持点随闭合并沿接近轴前移 17.44 mm**。PandaGripper 是平动指，夹持点固定。因此 ZhiXing **无法用单一固定 `grip_site` 在所有开合态精确重合**，残余 ~17 mm 是结构固有的（远小于 109 mm 的当前偏差）。

## 4. 候选修复（均**未落地**，待确认）

### 4.1 【高优先级】修正 ZhiXing 的 TCP 定义

**问题本质**：`zhixing_gripper.xml` 的 `<body name="eef" pos="0 0 0.12">` 把 `grip_site` 放在手指根部。策略的所有位置指令都作用在 `grip_site` 上，于是**整条轨迹的夹持点被系统性偏移 65～83 mm**。

**候选改法**：把 `eef` 前移到物理夹持点，使 `grip_site` 与咬合点重合。

| 选项 | `eef` 新位置 | 说明 |
|---|---|---|
| **A（推荐）** | `pos="0 0 0.20254"`（= 0.120 + 0.08254） | 以**闭合位**夹持点为准。抓取发生在闭合过程，且开爪接近时夹持点比 TCP 靠后 17 mm → **偏保守，不会顶进桌面** |
| B | `pos="0 0 0.18511"`（= 0.120 + 0.06511） | 以**全开**位为准。闭合瞬间夹持点会**越过** TCP 17 mm → 有顶入风险 |
| C | `pos="0 0 0.19380"` | 取行程中点，两端各偏 ±8.7 mm |
| D | 不动 XML，改为在挂载时覆写 | 不改资产，但需在 robosuite 侧加钩子，维护成本更高 |

**残留差异（结构固有，不可避免）**：ZhiXing 夹持点随开合沿接近轴移动 **17.44 mm**，单一固定 `grip_site` 无法在所有开合态精确重合。该残余可由自数据微调吸收，且相比 109 mm 已缩小 6 倍。

**连带影响**：
- `T_cam2grip` 将随 `eef` 前移而变化（相机在 hand 上不动，`grip_site` 动）；
- **初始位姿必须同步采用 §2.4 的候选 `init_qpos`**，否则改完 TCP 后起点会更低 82 mm；
- `GRIPPER_STATE_SELECTOR`、`_important_geoms`、动作维度、关节限位**均不受影响**（`grip_site` 是 site，不参与 state 构造）。

### 4.2 【高优先级】落地候选 `init_qpos`

与 4.1 配套。判据 (b) 已通过（0.0007 mm / 0.00001°），关节余量反而更宽裕（1.5424 rad）。建议与 4.1 **同一批次**落地并更新指纹。

### 4.3 【低优先级】相机占比对齐（列为后续消融，不在 N2 落地）

| 夹爪状态 | 占比比值 | 等效相机后移 | 等效 `fovy` |
|---|---:|---:|---:|
| reset | 1.355 | 31.6 mm | 75° → 83.5° |
| open | 1.456 | 39.8 mm | 75° → 85.6° |
| closed | 1.394 | 34.8 mm | 75° → 84.3° |

（一阶点源近似，像面积 ∝ 1/d²；实际值需经验扫掠确定。）

**为什么不在 N2 落地**：
1. **`eye_in_hand` 定义在 `robosuite/models/assets/robots/ECO65-B/robot.xml`，Panda 参考路径与 ZhiXing 路径共用**——直接改会同时改变 9/10 基线的视觉输入，破坏参考对照。必须做成**按夹爪条件化**的相机变体。
2. **不应与 TCP 修复同时改**：两个变量同时变化将无法归因。

**注意**：修 TCP **不会**改善视觉占比——相机在手上、夹爪几何不变，腕部渲染图逐像素不变；TCP 修复只改控制参考系。因此这两件事是**独立**的。
