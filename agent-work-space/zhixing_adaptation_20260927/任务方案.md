# ECO65 + ZhiXing：仿真数据采集、π0.5 微调与部署任务方案

日期：2026-09-27。目标目录：`/mnt/data/vla-policy/openpi/agent-work-space/zhixing_adaptation_20260927`。

## 目标与验收口径

最终目标为 ECO65 + ZhiXing 夹爪的高成功率适配。先完成 LIBERO 仿真端到端闭环，再进入实机阶段；仿真成功不能作为实机部署完成的依据。

用户已确认首阶段为 LIBERO Spatial 的 10 个任务，每任务 20 个独立保留场景，共 200 次正式测试；宏平均成功率目标 ≥90%，同时报告逐任务成功率、失败类型、置信区间和 Panda 参考。单任务低成功率不得被总平均掩盖。这是有限测试集上的验收指标，不是对未知环境真实成功率 ≥90% 的统计保证。

用户指定先完成方案制定；本轮仅检查资料、代码和资源、保存计划，不启动批量采集或训练。计算按约 40 GB 可用显存预算规划，实际启动前再次检查空闲显存。

原 ECO65 + PandaGripper 单轮结果 9/10 作为可运行参考，不能与 200 次新评测直接视为同精度指标。正式比较使用同一物体场景、预算和评测协议。

## 核心路线

**夹爪与控制可用 → 真实目标本体成功示范 → 数据校验 → 小规模微调 → 保留场景评测 → 失败补数 → 发布仿真配置 → 实机标定和验证。**

用户提出的仿真采集与微调路线可行。关键前提是成功示范必须由 ECO65 + ZhiXing 实际执行并渲染；不能把 Panda 图像/动作改名当作知行数据，不能把 0/10 策略的失败轨迹直接用作成功行为克隆数据。

## P0：冻结基线与目标本体体检

1. 保存机器人、夹爪 XML、控制器与训练代码的哈希；保存已有 9/10、碰撞修复与 IK 对齐记录。
2. 显式指定机器人和夹爪，保留 Panda 路径；不通过全局默认切换破坏参考实验。
3. 检查知行 6 关节初始化、equality/四连杆闭环残差、开合符号、开口范围、开合时间、末端 TCP 与实际夹持区域的关系。
4. 用固定目标检查知行负载下的末端跟踪；必要时针对该夹爪独立求解初始姿态，不照搬 Panda 的工具安装变换。
5. 验证空载开闭重复性、抓住目标后抬升/保持/松开。若不能可靠抓取，先修物理模型与控制；禁止用微调掩盖机械/仿真错误。
6. 对知行重新测量相机相对夹持点的变换和 TCP 定义。Panda 夹爪下的 6D 初始位姿对齐不自动等于知行已经对齐；知行的指尖几何与视觉占比不能假设与 Panda 一致。

第一批实验清单：原初始化/按关节约束自洽初始化对照；原开合速度/按秒标定速度对照；10 次空载开闭；6 个方向末端小幅平移及旋转；明确物体位置下的抓取—抬升 5 cm—保持 2 s—放回。抓持测试先达到至少 9/10 且无明显穿透/数值发散，再开始试采；仍需记录失败而非只保存成功。

产物：`scripts/audit_gripper.py`、原始测量、指纹、阶段结论。初期修正使用测试进程内开关，验证后再决定正式落地。

## P1：实现仿真采集链路与单任务试采

### 示范来源（按实际验证结果选择）

- 优先尝试仿真状态驱动的脚本专家：利用物体真实位置生成接近、抓取、抬升、搬运、放置、松开动作，仅用作数据教师；最终策略评测不能读取这些特权物体状态。
- 可用 Panda 成功轨迹提供任务顺序与末端路径候选，但必须在 ECO65 + ZhiXing 中重新执行、渲染、验证成功，重新记录实际控制指令和时间。相同增量动作不保证相同轨迹，夹持点偏移和闭爪时机必须针对知行重新校准；不能把轨迹直接重命名当作本体转换。
- 脚本难以覆盖的抽屉/遮挡场景，加入人工遥操作或修正示范。所有教师标明来源。

先在一个任务完成至少 5 条不同初始化的真实成功示范，检查抓持并非推碰或摆放初态导致的伪成功；再扩展到 10 个任务。失败轨迹保留作诊断，不进入初期成功示范训练集。

### 采集契约

- 20 Hz，分别保存外部与腕部 RGB、模型状态、机械臂/夹爪完整 qpos/qvel、实际执行的 7 维 OSC 增量指令、时间戳、阶段、成功信号。
- 每一帧为 **动作前观测 o_t 与实际执行动作 a_t**；不能将动作后图像与动作前标签错位。
- RGB 采用与当前 LIBERO 评测一致的 180° 翻转，明确记录方向和分辨率；不得用同一图像伪装两路相机。
- 保留完整状态，再构造独立、文档化的 8 维训练状态：`[grip_site xyz, grip_site 轴角, Left_1_Joint, Right_1_Joint]`，位置单位 m、角度单位 rad，并固定旋转坐标系约定。当前 π0.5 LIBERO 不以状态数值为条件，但仍需保持数据接口一致；禁止凭索引截取未知关节。
- 保存初始完整仿真状态、环境 XML、对象初态指纹、任务文字、随机种子、教师类型、动作缩放、夹爪配置和代码指纹，以便回放。
- 原生 OSC 平移缩放 0.05、旋转缩放 0.5，夹爪 -1 开/+1 合；实际值需从运行配置核验。保留零动作和等待时序，不能随意删除使时间语义变化。
- 以 episode 为单位原子保存，禁止覆盖已有成果；成功/失败分目录，训练集仅从审计通过的成功 episode 构建。建议原始记录采用 HDF5，数据集发布采用当前 LeRobot 版本；不是先生成 MP4 再反推训练帧。
- 成功判断以 LIBERO 原生任务谓词为主，同时记录物体是否真实抬升、放置后是否稳定，以及教师是否执行了预期抓放过程。训练标签不得来自仿真直接写物体坐标、焊接物体到夹爪等“作弊执行”。

## P2：数据扩展与 LeRobot 转换

1. 按场景划分训练、验证、最终测试，锁定 test 后不据 test 调参。种子不重叠之外，还核对对象初态哈希；相同轨迹的不同帧或渲染变体不能跨集合泄漏。
2. 初始目标每任务 50–100 条成功示范，共 500–1000 条；数量根据学习曲线调整，不保证仅靠数量达标。
3. 保存未筛选的所有采集尝试和成功比例，防止只报告筛选后的教师成功率。
4. 转换为当前仓库固定版本 LeRobot；features 为 `image`、`wrist_image`、`state`、`actions`、`task`，fps=20，不直接复制原示例的 fps=10。
5. 只对训练集计算归一化统计，验证 episode 数、帧数、类型、形状、有限值、动作范围、首末帧和回放结果。

建议分层扩展：先 1 任务 × 5–10 条试采 → 1–2 任务 × 20–50 条小训练验证 → 10 任务 × 50–100 条正式训练数据。较难任务可补到每任务 150–200 条；追加规模由独立验证结果决定。

正式测试初始化预先生成并冻结：每任务 20 个 seed/对象初态。训练 seed、验证 seed、测试 seed 分开命名和保存 manifest；若重复初始化产生相同对象状态，按哈希去重。最终测试失败不得被重新命名为“验证集”后反复调参；需要进入下一轮时建立新的未使用测试集。

数据质量检查至少包括：左右夹爪命名和符号正确；双相机内容确实不同；o_t/a_t 时间配对无偏移；控制频率与 fps 一致；没有 NaN/Inf；动作块不跨 episode 拼接；终止/尾部补齐遵守当前 loader；同一初态与轨迹不跨集合；随机抽查 10–20 条视频和原始动作回放。失败轨迹另存，不混入初期行为克隆。

## P3：π0.5 小规模微调

- 先从现有 `pi05_libero` 做同任务域目标本体适配；将 `pi05_base` 作为后续比较项，避免一开始同时改变任务先验和本体。
- 首先保持现有 `pi05=True, action_horizon=10, discrete_state_input=False` 和 LIBERO 动作语义；新增专用配置和数据资产，不覆盖官方配置。
- 服务器探测到单卡 NVIDIA GeForce RTX 4090、约 48 GiB 显存；探测时约 37 GiB 已占用且有其他评测运行。优先核验 JAX LoRA 支持与显存需求，训练与推理资源错峰；不停止未知任务。
- 依次进行数据加载检查 → 前向/反向 10–50 步 → 少量 episode 拟合 → 独立验证场景闭环。离线 loss 下降不足以证明适配成功。
- 完整训练时长由小规模实测吞吐和用户预算决定；不承诺固定步数可达到 90%。

### 首轮训练配置草案（待实测，不代表已写入训练代码）

| 配置项 | 计划值/原则 |
|---|---|
| 训练实现 | JAX，先使用仓库已有 LoRA 路径；不直接按约 40 GB 显存预算启动全参数微调 |
| 专用配置名 | `pi05_eco65_zhixing_lora` |
| 初始化权重 | 本机已有 `pi05_libero/params`，启动前解析真实缓存路径并核对版本 |
| 模型 | `Pi0Config(pi05=True, action_horizon=10, discrete_state_input=False, paligemma_variant="gemma_2b_lora", action_expert_variant="gemma_300m_lora")` |
| 动作维度 | 数据侧 7 维；模型内部保持 checkpoint 的 32 维 padding，不能随意改为 7 维 |
| 数据变换 | LIBERO 对应输入输出映射；`extra_delta_transform=False`，避免二次做 delta |
| 精度/EMA | bf16；LoRA 首轮 `ema_decay=None` |
| 冻结策略 | 使用匹配模型的 `get_freeze_filter()`，打印全部可训练参数；确认视觉编码器/投影层是否额外训练，再按显存调整 |
| Batch | 从 1–2 冒烟到 4/8，按峰值显存和吞吐调整；不假设已有梯度累积功能 |
| 学习率 | 先以 1e-5 至 5e-5 为候选区间，在验证集选择，不视为保证有效的固定值 |
| 步数 | 10–50 步技术冒烟；约 500–2000 步小数据可学习性检查；完整阶段按验证曲线和实际 episode 重复次数决定 |
| checkpoint | 独立目录，周期保存；以验证集闭环表现选最优，不能只选最低训练 loss |
| 统计量 | 仅从该版本训练集计算，并与 checkpoint 绑定；不擅自替换为测试数据统计量 |

本地代码已核对：`Pi0Config` 提供 LoRA 变体与冻结过滤器，`CheckpointWeightLoader` 支持补充缺失 LoRA 权重；这只是路径具备的静态证据，π0.5 + 目标数据的端到端训练仍需实际冒烟。尤其要确认载入权重并非大面积随机初始化、训练参数确实更新、保存重载后的推理行为一致。

显存规划：约 40 GB 应优先用于 LoRA 与小 batch，不能据此保证任意配置都能训练。探测时 GPU 总显存约 48 GiB、已有任务占用约 37 GiB；训练前需要有足够空闲显存并安排推理/训练错峰。对不是本任务启动的服务不自动终止。实测首个编译、稳定单步耗时、峰值显存、checkpoint 大小后，再给出完整训练时长和磁盘需求。

官方流程参考：[OpenPI 自有数据微调](https://github.com/Physical-Intelligence/openpi#fine-tuning-base-models-on-your-own-data)。具体实现以服务器本地依赖和代码版本为准。

## P4：闭环评测与失败补数

比较未微调/微调后的 ECO65 + ZhiXing、ECO65 + Panda 和 Panda 参考。固定任务场景、最大步数、动作块执行长度、相机预处理与随机性记录。

将失败分为：接近偏差、夹爪闭合过早/过晚、抓空、抬升滑落、搬运碰撞、放置错误、不可达/奇异、控制限幅等。优先补充训练/验证集中的失败类型，再重新训练；最终 test 只在候选版本冻结后执行。

主要指标：宏平均成功率、每任务成功率、95% 置信区间、完成步数、动作/推理延迟、异常终止数。评测不使用脚本专家干预，不读特权物体状态生成动作，不进行中途人工接管。固定 `replan_steps=5` 为首轮比较口径；若验证集表明需要改为 1/2，应视为新的部署配置并完整重评。

若收集更多数据或训练更多步未改善，应按顺序排查：训练/推理预处理一致性 → 动作与时间戳 → TCP/夹爪语义 → 数据成功质量与覆盖 → 训练是否实际更新 → 模型容量/冻结策略。不要盲目以更多失败数据或更长训练代替诊断。

## P5：仿真部署与实机分离验收

仿真发布包包含：机器人/夹爪配置、checkpoint、归一化统计、相机契约、动作尺度、控制频率、replan_steps、环境版本和一键回归命令；保留已知可用版本回退。

真实 ECO65 + ZhiXing 还需驱动接口、单位/坐标系、TCP/相机标定、控制时延、夹爪物理开口与力控、空载轨迹及抓取验证。需要真实设备连接与用户现场条件，不由仿真数据自动证明。

## 阶段闸门

| 阶段 | 进入下一阶段的条件 |
|---|---|
| P0 → P1 | 空载开合正常，初始化/约束残差可接受，目标能被实际抓持与抬升 |
| P1 → P2 | 至少一个任务的不同场景成功试采，动作—观测对齐和可回放检查通过 |
| P2 → P3 | 训练/验证/测试分离，转换和归一化检查通过，存在真实成功数据 |
| P3 → P4 | 小规模训练正常、独立闭环有效，无明显数据接口错误 |
| P4 → P5 | 冻结配置在保留场景达到双方确认的指标，报告分任务结果及不确定性 |

以下为顺利情况下的工程工作量估计，含调试，不是未经测量的算力运行时承诺；遇到夹爪建模问题会增加时间。
