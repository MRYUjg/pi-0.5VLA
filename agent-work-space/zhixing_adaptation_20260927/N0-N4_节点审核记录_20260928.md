# ECO65 + ZhiXing：N0–N4 节点审核记录

审核日期：2026-09-28。审核对象为服务器当前文件、节点总结、原始结果及采集数据。

**结论：不能认定 N0–N4 已全部验收完成，也不建议按当前版本直接扩大采集或开始微调。** 已有工作证明了夹爪极性/初始化缺陷、TCP 几何差异，以及部分标准试块的抓持能力；但当前版本存在基线回归、数据契约和回放验证缺陷。

用户所说“前四个节点”按 N0–N3 理解；同时审核 N4，因为它的后续改动已经影响前四个节点的有效性。本次只增加审核记录和独立探针，没有修改生产代码、资产、原始数据或旧总结，也没有重跑策略成功率评测。

## 1. 逐节点结论

| 节点 | 审核结论 | 可以保留的成果 | 尚未完成的验收 |

**“有成果”与“可放行下一阶段”需要分开。** 当前有价值的成果应保留，先修复下面的问题，再进入 N5。

## 2. 必须修复的问题

### R1 [P1] ZhiXing 专用初始关节角覆盖共用配置，Panda 对齐发生回归

位置：

- `third_party/libero/libero/libero/envs/robots/mounted_eco65.py` 的 `init_qpos`。
- `scripts/apply_zhixing_tcp_fix.py` 的落地逻辑。

两类都无条件返回 ZhiXing 专用解 `[-0.12639, -0.222035, -0.841572, -0.563545, 1.563635, -1.697476]`，即使显式传入 `PandaGripper` 也使用这一组关节角。

独立构建 LIBERO Spatial task 0，无策略、无渲染，比较 reset 后的 grip_site：

| 配置 | 世界位置 / m | 与 Panda 参考距离 |
|---|---|---:|
| Panda+Panda | `[-0.20846466, 0, 1.17327948]` | 参考 |
| 当前 ECO65+Panda | `[-0.20228703, 0.00006100, 1.28224800]` | **109.1435 mm** |
| 同模型仅在测试进程恢复旧 Panda 专用关节角 | `[-0.20846573, 0.00000048, 1.17327984]` | **0.001229 mm** |

这直接否定 N4 总结“ECO65+PandaGripper 的 9/10 基线均不受影响”的说法。**本次没有重新测策略成功率，因此不推断它现在是几/10；能确定的是初始条件已不再是原 9/10 的条件。**

修复：在环境构建/机器人初始化层按实际夹爪选择初始关节角，或者建立独立机器人变体；Panda 分支保留旧解，ZhiXing 分支使用新解。不要简单把所有类改回旧值，造成 ZhiXing 再次失配。随后做两分支 FK、相机回归和同协议策略复评。

证据：`review_20260928/current_probe.json`。

### R2 [P1] 采集首帧仍使用 reset 旧观测

位置：`scripts/n4_collect.py:397–439`、`:385–394`、`:190–213`。

`ep.start()` 保存 reset 观测，之后 `sample_object_init()` 重摆目标、`quiet_hold()` 又执行 45 步，但没有更新 `ep.obs`。第一次 `ep.act()` 使用旧图像/旧 eef 观测，却配上静置后的 qpos 和当前动作。

独立复现此路径：首帧图像落后 **45 个控制步，即 2.25 秒**，还包含目标重摆前的状态。旧观测夹爪关节仍为 `[-0.91, 0.91, ...]`，实际夹爪已打开到接近零。旧图与当前图相比：

| 相机 | 平均像素绝对差 / 255 | 发生变化的像素比例 |
|---|---:|---:|
| 外部 | 4.8362 | 11.62% |
| 腕部 | 12.0576 | 26.05% |

这是明确的首帧错误；没有据此宣称整个 episode 都错位。后续 `act()` 会更新 `self.obs`。

修复：初始化准备函数返回最后一步真实观测，并与 init_qpos/init_qvel 在同一状态边界一起保存；加一个重摆+开爪后首帧一致性检查。旧数据暂不直接进入训练，先确认可否删除错误首帧并同步重建初始状态，或者重新采集。

证据：`review_20260928/first_frame_probe.json`、`first_frame_*_stale_vs_actual.png`（左旧观测、右当前观测）。

### R3 [P1] 回放没有恢复夹爪速度与累积控制状态，不能归因于“接触混沌”

位置：`scripts/n4_audit.py:104–174`；`scripts/n4_collect.py:707`。

采集明确设置 `ZHIXING_GRIPPER_SPEED=0.01`，每条数据也记录了该值；审计脚本没有读取并应用它，干净进程默认是 **0.2**。另外，采集前经过 45 步开爪，`gripper.current_action` 已为 +1；回放 reset 后它是 0，仅恢复 qpos/qvel/warmstart 不会恢复这个累积命令。

用同一条 `n4_libero_object_t0_s2_0002.npz` 做三组独立完整动作回放：

| 回放配置 | 首步夹爪最大角误差 | 第 60 步夹爪最大角误差 | 末尾原生成功谓词 |
|---|---:|---:|---|
| 默认 speed=0.2，累积命令=0 | 0.067869 rad | 1.331371 rad | False |
| speed=0.01，累积命令=0 | 0.315370 rad | 0.000032 rad | True |
| speed=0.01，恢复累积命令=+1 | **0.000020 rad** | **0.000060 rad** | True |

这说明配置和控制器状态恢复是已证实的问题；并不表示第三组已实现全程逐位一致。该组末期仍有偏差，仍需继续恢复/检查控制器缓存与完整状态。

现有审计还会把回放异常、早期回放失败仅写进结果，不纳入最终 `all(c.values())`。它用“动作与位移方向点积为正 ≥95%”替代配对验证，但已有结果中 seed 2 的 lag0 与 lag+1 同为 0.975，seed 3 两者同为 1.0，其他样本甚至 lag−1 更高。这项检查不能排除一帧错位，更未验证图像对应状态。

修复：严格重建每条数据的环境配置、夹爪累积状态、控制器状态及仿真状态；回放异常和超过预定义阈值必须使验收失败。按臂关节角、夹爪关节角、物体位置和姿态分别比较，不把混合 qpos 最大差统称为 rad。增加可辨别的短动作序列和图像/状态一致性测试。完整状态保存与容差应在扩大采集之前固定。

证据：`review_20260928/replay_probe.json`。本次只对一条示范做了三配置完整回放，不能外推为另外四条已验收。

文档声明最后两维是 `Left_1_Joint, Right_1_Joint`，且按名字查找；实际代码硬取夹爪数组 `[1,5]`，编译模型显示是：

证据：`review_20260928/current_probe.json`。

### R6 [P2] OSC 动作尺度元数据写成了教师伺服增益

位置：`scripts/n4_collect.py:55–56`、`:615–616`。

NPZ 元数据写 `osc_pos_scale=0.02`、`osc_rot_scale=0.05`；实际构建的 LIBERO `OSC_POSE` 控制器 `output_max` 是：

```text
[0.05, 0.05, 0.05, 0.5, 0.5, 0.5]
```

即满量程目标增量分别为 0.05 m 和 0.5 rad。教师用来除位置/旋转误差的常量不是底层动作单位，也不能用实际单步位移替代控制器目标尺度。

已存 actions 确实是传入 env.step 的归一化 7 维动作，不应因此随意重缩放旧标签。修复应将教师增益与实际 controller input/output range 分开保存，回放/训练/部署按同一动作合同处理。

证据：`review_20260928/current_probe.json`，编译模型与 `robosuite/controllers/config/osc_pose.json` 一致。

### R7 [P2] N3 的通过口径比完整抓放能力窄

位置：`scripts/n3r_block_test.py:252–258`、`:303–312`、`:401–405`，以及 `scripts/n3_grasp_test.py` 的 `ik_goto/step_hold`。

- 历史最终实验使用 OSC 抬升和保持，这部分可保留；但接近/下降仍通过 IK 直接写 qpos，闭合时每个子步锁臂，放回也使用 IK 覆写。不是完整七维动作链的抓取—放回测试。
- `success` 仅为 `dz_hold_mm > 30`，未要求放回稳定、接近无瞬移、完整过程穿透合格等。最终 30 mm 组中 `dz_end_mm` 最低为 −20 mm，也没有影响 PASS；这个值应单独解释和验证，不能据它直接断言某种最终姿态。
- 总 verdict 使用 `any_width_pass`，任一宽度达到 9/10 就 PASS。30/50 mm 的结果不能推广到所有宽度；70 mm 仍是 8/10，更没有证明“≤85 mm 任意实体都能抓”。
- B 结果只有 ±x/±y/±z 六个平移测试，没有原计划中的旋转测试。
- 旧脚本仍使用 `GRASP_OFFSET_CLOSED=82.54 mm`。当前 TCP 前移后这个常数失效；旧总结已提示该问题，但脚本尚未形成可安全重跑的验收入口。
- “无穿透”与记录中的约 0.82–1.12 mm 接触穿透不是同一表述。应定义允许的软接触穿透阈值并检查全程峰值，而非把负值直接称为零穿透。

修复：在当前资产和实际部署速度下，完成全程 OSC 抓取、抬升、保持、放回测试；明确物体/初态分布与各项阈值；补旋转跟踪。原始试块结果保留为有限台架能力证据。

## 3. 版本、任务范围与结论的其他问题

### 3.1 N0 冻结清单不是当前版本

重跑原验收脚本的静态部分，退出码为 1：

```text
N0: 5/6
b_source_hashes_match_manifest:
  eco65_robot_py: 4ac890d5 != 27ac09fa
  mounted_eco65_py: a9048a37 != 3c828ad6
NODE_VERDICT = INCOMPLETE
```

旧 manifest 不包含关键 `zhixing_gripper.xml`、新地面机器人类、OSC 配置和采集/回放脚本；其依赖版本探测 `container_versions.ok=false`，日志是 `NameError: name 'python' is not defined`。因此“依赖版本全部入库”不成立。

`configs/` 为空。历史基线可作为历史证据保留，但必须新增“当前候选版”独立指纹、参数和可恢复资产集，不能覆盖历史记录后宣称它仍是同一个基线。

此外 N0 的 Panda 复跑使用 `auto→init_state`，而原 10/10 阳性对照是 `random`；它复现的是另一个 8/10 协议。ECO65 与 Panda 的对照需要显式固定同一初始场景口径。推理 RNG 确实随请求历史推进，但这不能单独证明所有波动“纯粹由 RNG 引起”；文档引用的 `jax.random.beta` 是训练 compute_loss，而非推理 sample_actions。

### 3.2 N2 机器可读契约仍是修复前版本

`results/tcp_camera_contract.json` 仍写：候选未落地、旧初始角、相机变换差 23 mm、夹持点前伸 82.54 mm。这可以作为历史标定记录，但不再是当前部署的权威契约。

当前 eef 已从 0.120 改为 0.20254，必须生成新版本契约，绑定当前 XML、机器人类和控制参数，并重新测量 TCP、相机变换、开/闭状态和初始位姿。报告中列出的 `n4_verify_tcp_fix_*.json` 在本次目录检查中未找到，不能用产物清单代替落盘证据。

### 3.3 Spatial 换成 Object，尚未形成统一的最终验收协议

用户此前确认的是 Spatial 10 任务 ×20 次、总成功率 ≥90%。N4 写“D1 决策”改为 `libero_object`，但当前 `阶段进展.md` 仍写 Spatial。审核不能从这些文件判断其他会话里的授权内容；**无论变更是否曾获同意，工程验收口径都应统一写入版本化协议。** Object 单任务试采不能算 Spatial 的高成功率目标已经推进到相同验收阶段。

还需解决两点：

- 当前成功示范为 **447–459 步**，现有 Object 评测入口上限是 **280 步**。这不证明微调策略必然失败，但教师示范尚未证明能在目标评测时限内完成。应缩短无效等待/优化控制，或者明确调整时限并对全部对照使用同一新协议。
- “黑碗外径大于开口”只排除了包住全宽的特定抓法，不能单独证明夹边/侧抓等所有抓法均不可行；单个固定姿态、有限初值 IK 求解失败也不能证明目标在所有姿态下物理不可达。相关结论应限定为“当前抓取方式/求解条件下失败”，继续调查后再决定任务覆盖范围。

### 3.4 “视觉 OOD 是主因/微调是必经之路”尚未被严格隔离证明

修极性后仍 0/10、腕部图像不同、夹爪输出模式异常，都支持视觉分布变化的怀疑；但后续又发现 TCP、碰撞/力学和控制时序问题，说明这些混杂因素此前未排除。

应先在最终物理/控制配置下复评，再做保持其他条件一致的视觉消融或自数据微调实验。当前结论宜为“视觉和策略分布适配仍待验证”，避免用它解释所有剩余失败。

### 3.5 可以接受的偏离及文档勘误

- 原始格式从 HDF5 改为压缩 NPZ，本身不是不通过原因；数组、契约、追溯和原子保存满足要求即可。
- 服务器确实保存了 `raw/failure/n4_libero_object_t0_s1_0001.npz`；N4 产物表写“本轮为空”已过时。应表述为 **6 次尝试、5 成功、1 失败**。
- 五条成功记录的 collector 哈希与当前采集脚本一致。每条最后一帧均为 release，尚无 retreat 帧；原生成功第一次成立即停止，不等于已经验证稳定放置后的持续成功。

## 4. 建议返工与复验顺序

1. **先保护数据**：移除默认清空入口，保留现有成功/失败数据及历史结果。
2. **隔离夹爪配置**：恢复 Panda 专用初始化，保留 ZhiXing 专用初始化；冻结当前资产、控制器、速度与套件。
3. **修复采集/回放合同**：首帧观测、命名关节、真实动作尺度、完整仿真与控制器状态；把回放失败接入验收，不以平滑轨迹方向一致率替代。
4. **当前版本重验 N1–N3**：开合时序、TCP/相机、平移+旋转、全程 OSC 抓放；与 Panda 的同协议基线回归一起完成。
5. **重验 N4**：至少五条不同初始化成功示范、所有尝试留档；逐条回放成功，状态误差阈值明确，图像/状态/动作配对正确；增加释放后的稳定确认。另明确教师与正式评测步数限制。
6. **固定目标协议后进入 N5**：Spatial 或 Object、全部任务覆盖、每任务测试数量、时限、随机性控制及 Panda 对照都写清楚，再扩大采集和微调。
