## 1. 修复内容

### 1.1 开合极性反转

**问题**：`ZhixingGripper` 的 action 语义与 robosuite/LIBERO 统一约定（`+1=闭合`）相反。

robosuite 用 `ctrl = bias + weight × u` 把归一化动作映射到执行器
（本夹爪 `ctrlrange=[-0.91, 0]` → `bias=-0.455`、`weight=0.455`）：

| u | q_target | 实测指尖开口 | 实际动作 |
|---|---|---|---|
| `+1` | `0.00` | **11.26 cm** | **张开** ❌ |
| `-1` | `-0.91` | **2.28 cm** | **闭合** ❌ |

PandaGripper 在同一机器人、同一协议下的对照：`+1` → 0.10 cm（闭合）、`-1` → 7.94 cm（张开）。

**修复**：`format_action` 的累积项取负。

```python
# 修正前
self.current_action = np.clip(self.current_action + self.speed * np.sign(action), -1.0, 1.0)
# 修正后
self.current_action = np.clip(self.current_action - self.speed * np.sign(action), -1.0, 1.0)
```

### 1.2 `init_qpos` 严重不自洽

**问题**：`init_qpos` 返回单元素 `[-0.91]`，被 `SingleArm.reset()`
(`robosuite/robots/single_arm.py:181`) 赋给全部 6 个夹爪关节索引 → 广播成 `[-0.91] ×6`。
但 XML 的 5 条 joint equality 要求 `Left_Support / Right_1 / Right_2 / Right_Support = -Left_1 = +0.91`。

后果（实测）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 最大 joint equality 残差 | **1.82 rad（≈104°）** | **0.0** |
| 左侧四连杆 `conn_left` 残差 | **34.73 mm** | **7e-8 m** |
| 右侧四连杆 `conn_right` 残差 | 2e-7 m | 1.8e-7 m |

**修复**：按 `Left_1 = -0.91` 反解出其余 5 个关节，返回自洽的 6 元素数组。

```python
return np.array([-0.91, 0.91, -0.91, 0.91, 0.91, 0.91])
```

> ⚠️ **注意**：`-0.91` 是执行器行程的**接近闭合**端（开口 ≈2.3 cm），**不是**原注释所说的
> "fully open"。全开对应 `Left_1 = 0`（开口 11.26 cm）。
> 若希望 reset 时全开，把 `-0.91` 改成 `0.0` 即可（得到 `[0]*6`，同样自洽，且是 XML 装配零位）。
> 本次**保留了原声明的数值**，只修不自洽，不夹带改变 reset 姿态的设计决策。

## 4. 回归评测

| tag | 配置 | 成功率 | 对比 |
|---|---|---|---|
| `N1_fix_eco65_panda_regress` | ECO65 + **PandaGripper** | **9/10** | 与历史基线 `H_eco65_panda_align` **9/10 完全一致**，连失败任务（on the wooden cabinet）都相同 → **无附带损害** ✅ |
| `N1_fix_zx_final` | ECO65 + **ZhiXing**（修复后默认） | **0/10** | 与修复前一致（10 个任务全失败） |

**结论**：
1. 修复**没有**影响 Panda 路径（符合预期：改动只在 `ZhixingGripper` 类内）。
2. 修复**不足以**恢复 ZhiXing 的成功率 —— 与 N1 的开关版实验（0/10 → 0/10）结论一致，
   再次确认 **0/10 的主导阻塞在策略侧视觉 OOD**，自数据微调/视觉对齐仍是必经之路。
3. 但这两项修复是 **P1 数据采集的前置条件**：若带着反转极性采集示范，数据会把「张开」
   标成 `+1`，训练出的策略继承错误的夹爪约定。
