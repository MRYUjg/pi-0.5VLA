## 1. 已确认的验收范围

| 项 | 值 |
|---|---|
| suite | `libero_spatial` |
| 任务数 | 10 |
| 每任务测试次数 | 20 |
| 总测试次数 | **200** |
| 宏平均成功率目标 | **≥90%** |

必报项：逐任务成功率、失败类型分布、95% 置信区间、完成步数、推理延迟、异常终止数、Panda 参考。

> 这是**有限测试集上的验收指标**，不是对未知环境真实成功率 ≥90% 的统计保证；单任务低成功率不得被宏平均掩盖。

## 2. 当前偏离（未获书面确认）

- **事实**：N4 试采与评测改用了 libero_object 的**单任务（task 0）**
- **影响**：Object 单任务试采**不能**算作 Spatial 10×20 的验收目标已推进到同一阶段；它可以作为**链路打通与数据契约验证**的试点，但不能对外表述为「成功率目标已推进」。
- **裁决**：`RESOLVED`
- 用户选择 **(A)：最终验收保持 libero_spatial，10 任务 × 20 次 = 200 次，宏平均 ≥90%**。Object 单任务试采仅作为链路与数据契约的试点，不计入 Spatial 的验收进度，也不得与 Spatial 数字混比。

## 3. 时限冲突（阻塞跨配置比较）

- 教师成功示范实测帧数：[517, 521, 521, 523, 529]
- 评测入口上限：`{"libero_spatial": 220, "libero_object": 280, "libero_goal": 300, "libero_10": 520, "libero_90": 400}`（libero_object=280，libero_spatial=220）
- **这个上限是不是写死的**：**不是硬约束**：`MAX_STEPS` 只是 `agent-work-space/scripts/eval_matrix.py:36-42` 与 `examples/libero/main.py:92-100` 里的两个字面量字典，取值沿用官方 LIBERO 约定（注释写 longest training demo has N steps）。可以改，但改了就不再与官方协议及历史 Panda 参考同口径。
- **问题**：评测入口上限（Object 280 步 / Spatial **220 步**）小于教师示范长度。这不证明微调后策略必然失败，但说明**教师示范尚未证明能在目标时限内完成**。

### 教师耗时诊断（决定该不该动上限）

- 逐 episode 的 `phase_end` 显示：**transport 恒为 220 步、place 恒为 160 步**（5/5 完全一致），即两段 `servo()` 都返回了 `max_steps` —— **从未满足其 8 mm 容差**，属超时退出而非收敛。
- 约 521 帧里有 **380 帧（73%）** 花在两段未收敛的伺服上。所以时限冲突的首要原因是**教师控制质量**，而不是任务本身需要 520 步。
- **尚未隔离**：尚未隔离「为何不收敛」，候选：① 刻意降低的 gain=0.55（为防惯性滑落）；② `robosuite/robots/single_arm.py` 中 joint_kp=3.0 的关节 PD 回拉在**带载**时造成稳态误差；③ 目标点不可达。需要一次带载稳态误差实测才能定因。

可选方案：

- (A) 缩短教师：先定位上面三个候选原因，让 transport/place 真正收敛、或在达标后提前退出；预期可把示范压到 220 步以内（**首选，审核记录也要求「缩短无效等待/优化控制」**）；
- (B) 放宽时限：把该 suite 的 max_steps 提高并重新冻结；

> **规则**：无论选哪个，**同一时限必须同时施加于全部被比较配置**（微调前后 ECO65+ZhiXing、ECO65+Panda、Panda 参考），否则成功率不可比。选定值写入 configs/frozen_protocol.json。

## 4. 随机性与对照

- 同一次比较内固定同一种初始场景口径（random 或 init_state），并把该口径写入结果 JSON。历史记录显示 `auto→init_state` 复现的是8/10 协议，而 10/10 阳性对照用的是 random —— 两者不可混比。
- 推理 RNG 随请求历史推进；不得把全部波动都归因于 RNG，也不得用 RNG 解释跨口径差异。
- 训练 / 验证 / 测试 seed 分别命名并保存 manifest；重复初始化按对象初态哈希去重。
- Panda 参考：Panda+PandaGripper 必须用与目标配置**完全相同**的 suite、任务、seed、时限、动作块长度与相机预处理重跑，不得引用历史数字代替。
- `replan_steps = 5`；若验证集表明需改为 1/2，视为**新的部署配置**并完整重评。
- 评测纪律：不使用脚本专家干预；不读特权物体状态生成动作；不进行中途人工接管；固定并记录 max_steps 与动作块执行长度

## 5. 结论边界（必须随结果一起引用）

- **黑碗可达性**：「黑碗外径大于开口」只排除了**包住全宽**这一种抓法，不能证明夹边/侧抓等所有抓法都不可行；单个固定姿态、有限初值 IK 求解失败也不能证明目标在所有姿态下物理不可达。相关结论必须限定为「在当前抓取方式 / 求解条件下失败」。
- **视觉 OOD**：「视觉 OOD 是主因、微调是必经之路」尚未被严格隔离证明：后续又发现 TCP、碰撞/力学与控制时序问题。当前结论宜为「视觉与策略分布适配仍待验证」，需在**最终物理/控制配置**下复评后，再做保持其他条件一致的视觉消融或自数据微调实验。
