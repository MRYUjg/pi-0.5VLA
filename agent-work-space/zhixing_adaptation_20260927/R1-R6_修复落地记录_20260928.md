## 2. R1 — 按夹爪隔离初始关节角

**问题**：`eco65_robot.py` 与 `mounted_eco65.py` 的 `init_qpos` **无条件**返回 ZhiXing 专用解
`[-0.12639, -0.222035, -0.841572, -0.563545, 1.563635, -1.697476]`，即使显式传入 `PandaGripper`。
实测 ECO65+Panda 的初始 `grip_site` 因此偏离 Panda 参考 **109.1435 mm**。

**根因（解析时序）**：`Robot.load_model()` 在 `SingleArm` 调用 `add_gripper()` **之前**就执行
`self.init_qpos = self.robot_model.init_qpos`，此时机器人模型的 `self.grippers` 仍为空 ——
所以单靠把 `init_qpos` 写成"看夹爪"的属性并不够，必须再补一次**重新解析**。

**修复**：

| 文件 | 改动 |
|---|---|
| `robosuite/models/robots/manipulators/eco65_robot.py` | 新增唯一真源 `ECO65_INIT_QPOS_BY_GRIPPER`（Panda 解 / ZhiXing 解）与 `eco65_init_qpos_for_model()`；`init_qpos` 改为按实际挂载夹爪分派 |
| `third_party/libero/libero/libero/envs/robots/mounted_eco65.py` | **导入同一张表**，避免两处约定漂移 |
| `robosuite/robots/robot.py` | 新增 `_init_qpos_explicit`，记录调用方是否显式指定 |
| `robosuite/robots/single_arm.py` | `add_gripper()` 之后**重新解析**默认 `init_qpos`（显式传入者优先，不被覆盖） |

未登记夹爪会 `warnings.warn` 并回退到 Panda 解（不静默）。

**验证**：`scripts/verify_r1_gripper_init.py` → `results/r1_gripper_init_verify.json`，**10/10 检查通过**：

```
未挂载夹爪        → [-0.128227, -0.080175, -1.482052, -0.064915, 1.563529, -1.699308]  (兜底)
挂 PandaGripper   → [-0.128227, -0.080175, -1.482052, -0.064915, 1.563529, -1.699308]

```

关键判据 `robot_zhixing_branch_reresolved_ok` 通过：预解析阶段必然拿到 Panda 兜底解，
只有**重新解析真的生效**才会变成 ZhiXing 解 —— 这一条同时证明了时序修复有效。
`explicit_override_wins` 通过：显式传入的 `initial_qpos` 不被覆盖，其它入口不受影响。

## 4. R3 — 回放：严格恢复 + 硬判据 + 配对判别力（`scripts/n4_audit.py`）

### 4.1 恢复环境配置

采集用 `ZHIXING_GRIPPER_SPEED=0.01` 并逐条写入元数据；审计脚本原先不读取它，
干净进程按资产默认 **0.2** 跑。现在每条 episode 回放前显式
`os.environ["ZHIXING_GRIPPER_SPEED"] = meta["gripper_speed"]`，并断言生效。

### 4.2 恢复夹爪累积控制状态

`ZhixingGripper.format_action`（`dof=1`）是**累加式**：
`current_action ← clip(current_action − speed·sign(a), −1, 1)`。
采集前 45 步开爪指令已把它推到 **+1**；`reset()` 后它是 0。
只恢复 qpos/qvel/warmstart 不够。现在：

- 采集侧新增落盘 `init_gripper_current_action`（与 qpos/qvel/warmstart 并列，属控制器状态）；
- 审计侧优先从 NPZ 恢复；旧数据无此字段时按准备阶段步数**重建**并在结果里标明来源
  （`reconstructed_from_prep_hold(45)`），不假装是原始状态。

### 4.3 分类比较

不再把混合 `qpos` 最大差统称为 "rad"。现在分开统计臂关节角、夹爪关节角、
物体位置（m）、物体姿态（rad），并给出自由空间段窗口内的最大值。

### 4.4 硬判据

回放异常与超阈值**必须使验收失败**，不再只写进结果：

| 判据 | 阈值 | 实测（n4v2） |
|---|---|---|
| `replay_no_exception` | 无异常 | 通过 |
| `replay_free_space_arm_within_tol` | < 0.01 rad | **6.4409e-05 rad** |
| `replay_free_space_gripper_within_tol` | < 0.01 rad | **2.5444e-05 rad** |
| `pairing_replay_render_matches` | 渲染 vs 存档 < 3.0/255 | **≤ 0.003/255** |
| `obs_state_consistent` | lag0 中位数 < 1e-4 m | **1.038e-06 m** |
| `obs_state_lag0_better_than_shift` | 平移一帧 > 10× | **25.9× / 23.9×** |
| `pairing_detector_has_discriminating_power` | 自检 lag0 最优 | 通过 |

修复前（审核记录 R3）：speed 不恢复时首步夹爪角误差 **0.3154 rad**；恢复 speed 但累积命令=0 时
仍有 0.3154 → 0.000032 的差异；本次三项同时恢复后自由空间段降到 **1e-5 rad 量级**。

### 4.5 配对判别力：一个必须记录的负面结论

审核要求"增加可辨别的短动作序列和图像/状态一致性测试"。实现过程中得到一个**重要负面结果**：

> **基于"动作 × 位移方向/幅度"的滞后判别法没有判别力**，因为它无法区分 lag 0 与 lag −1。
> 原因是 OSC 底层控制器存在约一个控制步的响应滞后，位移与**上一步**指令的拟合优度天然接近甚至更好。
> 实测诊断残差 `{lag0: 0.4913, lag+1: 0.7477, lag−1: 0.3286}` —— lag−1 反而最小。

因此该方法被**降级为诊断项**（字段名加 `_diagnostic` 后缀），配对判据改由**回放渲染**承担：
若动作错位一帧，重放轨迹会偏离，渲染画面必然对不上存档图像。

为证明新判据**确有判别力**，`--selftest` 用刻意可辨别的短序列（6 方向突变 ×3 步）做 ±1 帧对照：

```
±1 帧回放渲染误差 = {lag 0: 0.128,  lag +1: 0.258,  lag −1: 0.309}   → lag0 最优 = True
```

即 lag0 的渲染误差只有错位一帧的 **1/2 ~ 1/2.4**，检测器有判别力。

### 4.6 另一个必须记录的测量细节

`obs_state_consistent` 最初按"FK(qpos[t]) 必须逐位等于存档 `eef_pos[t]`"实现，实测最大 **7.678e-04 m**，
不能通过 1e-6 的严格阈值。逐帧诊断后确认这**不是配对错误**：

```
FK(qpos[t])   vs 存档 grip_site[t] : 中位数 1.038e-06 m，最大 7.678e-04 m（t=63）
FK(qpos[t+1]) vs 存档 grip_site[t] : 中位数 2.690e-02 m   ← 平移一帧差 26 倍
```

原因是 MuJoCo 的 `site_xpos` 由 `mj_forward` 产生，而 `mj_step` 之后 `qpos` 已积分、
`site_xpos` 仍对应本步 forward 的状态，因此同一帧内二者存在**亚子步**级偏差，幅度与运动速度成正比。
结论：lag 0 是正确配对（用中位数判定 + 平移一帧对照），绝对偏差作为**已知保真度上限**记录。

## 5. 新旧数据对照：修复后的审计确实会拒绝旧数据

用同一个（修复后的）审计脚本分别跑旧数据与新数据，是验证"判据是否真的有效"的最直接方式：

| 数据 | tag | 结果 | 失败的检查项 |
|---|---|---|---|
| 返工前采集的 5 条成功 | `n4_libero_object_*` | **5/5 全部不通过** | `state_joint_names_are_active`、`controller_output_max_recorded`、`controller_output_max_matches_osc`、`teacher_gain_separated`、`frames_obs_in_sync`、`first_frame_obs_fresh`、`eef_pos_equals_grip_site` |

失败项与审核记录的缺陷一一对应：R4 → `state_joint_names_are_active`；
R6 → 三个 `controller_output_max_*` / `teacher_gain_separated`；R2 → `frames_obs_in_sync`、`first_frame_obs_fresh`。

其中 **`eef_pos_equals_grip_site`** 是一条**独立**佐证 R2 的判据：`robot0_eef_pos` 与记录的
`grip_site` 本质是同一个 site（`eef_site_id == gid == 13`），新数据两者逐位相等（max 0.0），
旧数据不相等 —— 因为旧实现第 0 帧的 `eef_pos` 来自 reset 时刻的过期观测，
与同帧的 `site_xpos` 不是同一状态。这条检查与 `obs_step` 账本互相独立，
却指向同一个缺陷。

新数据同时满足初始化多样性：5 条 `init_qpos` / 物体初态指纹 / 采样 xy **两两不同**，
最小两两间距 **13.56 mm**（> 8 mm 门槛）。

- 五条成功记录的 collector 哈希与当时采集脚本一致；每条最后一帧均为 release，
  **尚无 retreat 帧**；原生成功第一次成立即停止 ≠ 已验证稳定放置后的持续成功 ——

  「视觉与策略分布适配仍待验证」，并写入验收协议 §5。
