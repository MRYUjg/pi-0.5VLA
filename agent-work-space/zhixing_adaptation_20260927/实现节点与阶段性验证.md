# ECO65 + ZhiXing 适配：实现节点与阶段性验证

日期：2026-09-27。
依据：`任务方案.md`（P0–P5 路线）、`阶段进展.md`，以及截至本日的三项已落地改动与全部评测证据。
用途：把方案转成 **9 个可执行节点（N0–N8）**，每节点给出「进入条件 / 验证动作 / 通过判据 / 证据产物 / 未通过回退」，作为后续执行与验收的唯一口径。

> 一句话现状：**ECO65 + PandaGripper 已经可用（9/10，Panda 参考 10/10），ECO65 + ZhiXing 仍是 0/10；0/10 的主因已被定位为腕部视觉 OOD 导致的策略决策偏移，而不是夹爪开合速度。**

### 1.2 评测事实（同协议：`libero_spatial` 10 任务 × 1 次、`seed=7`、`replan_steps=5`、随机初始化）

| tag | 机械臂 | 夹爪 | 成功率 | 说明 |
|---|---|---|---|---|
| `D_panda_panda_randinit` | Panda | PandaGripper | **10/10** | 阳性对照 |
| `H_eco65_panda_align` | ECO65 | PandaGripper | **9/10** | ← **当前可用基线**，残余失败为 "on the wooden cabinet"（230 步） |
| `F_eco65_panda_contactfix` | ECO65 | PandaGripper | 6/10 | 仅自碰撞修复、未对齐位姿 |
| `B_eco65_panda` | ECO65 | PandaGripper | 0/10 | 修复前 |
| `A` / `G_eco65_zhixing_contactfix` | ECO65 | **ZhiXing** | **0/10** | 修复前后均 0/10，10 任务全部跑满 230 步 |
| `E_panda_zhixing` | Panda | **ZhiXing** | **0/10** | **只换夹爪**即使 10/10 的 Panda 也崩到 0/10 |
| `F_eco65_zhixing_speed001` / `G2_panda_zhixing_speed001` | — | ZhiXing | 0/10 | `speed=0.01`（对齐 Panda）**无任何改善** |
| `entry_panda` / `entry_zhixing` | ECO65 | Panda / ZhiXing | 10/10 / 0/10 | 真实入口 `examples/libero/main.py`，`Caught exception` 均为 0 次 |

**已确认的因果链（有直接证据）**：

```text
腕部画面里是 ZhiXing（外观与训练分布不同）
      └─→ 策略从第一步起持续输出 +1（闭合），而非 -1 保持张开 → 到位后 +1
            └─→ 爪子还没碰到物体就已经闭上
                  └─→ 抓空 → 0/10
```

开合速度处于这条链的**下游**（只决定闭得多快），所以把它从 0.2 改到 0.01 无效——假设已被消融实验推翻。

### 1.3 ZhiXing：已确立事实 vs 尚未测量

| 已确立 | 尚未测量（P0 待补） |
|---|---|
| 6 关节，state 取 `gripper_qpos[[1,5]]`（两个 Support 关节，**旋转量**，与 Panda 的平动指关节物理含义不同） | **TCP / `grip_site` 相对指尖的实际夹持区** |
| `format_action` 累加式，`speed=0.2`，每个 env step 被调用 25 次 → **单步内饱和（bang-bang）** | **开 / 闭的符号方向**在动作语义上是否正确 |
| 6 关节负载下 **`init_qpos` 只有 `[-0.91]`，被广播到 6 个关节**，与 XML 里 5 条 equality 约束的初始关系不符 | **开口范围**（全开/全闭的实际几何行程） |
| 几何差异：`grip_site` 距基座 **0.12 m**（Panda 0.097 m）、指长/指宽不同 | **开合时间**的真实标定（按秒） |
| 接触力学差异：1 个 actuator `kp=100` + 5 条 equality 联动（Panda：2 个 actuator `kp=1000` + 限力 ±20 N） | **腕部相机相对 ZhiXing 夹持点的变换 `T_cam2grip`** |
| 装上后策略指令从「-1 保持张开→+1 闭合」变为「**+1 全程闭合**」 | **抓住目标后的抬升 / 保持 / 松开**是否可靠 |
| 失败现象：夹爪压在盘子上、把餐具撞翻、始终没夹住碗（`G_eco65_zhixing_contactfix__agentview__f219.png`） | 闭环残差、穿透、数值发散 |

> ⚠️ 重要边界：`T_cam2grip` 在 Panda 与 ECO65(PandaGripper) 之间曾逐元素相同（平移差 0.000 mm），**但这条结论只对 PandaGripper 成立**。换成 ZhiXing 后指尖几何完全不同，必须**重新测量**，不能沿用。

### 1.5 需先消除的两处口径不一致（执行前确认）

1. **`default_gripper` 的当前值**：`换机械臂为何变差_分析.md` 记录已改为 `"PandaGripper"`；而更晚的 `入口夹爪分派_20260927.md` 明确写「**未改动**……仍为 `ZhixingGripper`」。以最新文档为准（默认 ZhiXing，Panda 走 `--args.gripper PandaGripper`），但**必须在 N0 实测确认**，否则后续「是哪条路在跑」会失真。

## 3. 阶段性验证（闸门判据）

> 每个节点都必须先满足「进入条件」才能开工；「通过判据」全部量化，且**不以训练 loss 或单次运气作为通过依据**。

### N0 — 基线冻结与指纹

| 项 | 内容 |
|---|---|
| 进入条件 | 无（起点） |
| 验证动作 | ① 对 8 类文件取 sha256：`ECO65-B/robot.xml`、`zhixing_gripper.py`、`eco65_robot.py`、`mounted_eco65.py`、`examples/libero/main.py`、`eval_matrix.py`、`serve_policy.py`、`src/openpi/training/config.py`；② 记录 docker 镜像名与依赖版本；③ 实测并打印两个 ECO65 类的 `default_gripper` 实际值；④ 用 `seed=7` 重跑两格复现 |
| **通过判据** | (a) 复现 **ECO65+PandaGripper = 9/10**、**Panda+PandaGripper = 10/10**；(b) 哈希清单与实际文件逐一一致；(c) 三项已落地改动均有对应 `.bak` 且可恢复；(d) 明确记录默认夹爪的真实值 |

### N1 — ZhiXing 本体体检

| 项 | 内容 |
|---|---|
| 进入条件 | N0 通过 |
| 验证动作 | ① reset 后检查 6 关节实际 qpos 与 XML 5 条 equality 的**闭环残差**；② 把 `init_qpos` 从单值广播改为**与约束自洽的 6 元素**（测试进程内开关）；③ 用固定指令验证**开合符号**（-1 开 / +1 合是否成立）；④ 测定**全开/全闭实际开口范围**与**按秒标定的开合时间**；⑤ 复测 `speed` 0.2 vs 0.01 对照 |
| **通过判据** | (a) 闭环残差 ≤ 求解器容差且 reset 后无可见跳变；(b) 开合符号与动作语义一致，**无反向**；(c) 开口范围有数值区间记录，与几何一致；(d) 开合时间有按秒标定值；(e) 无 NaN/Inf、无穿透、无数值发散 |
| 证据产物 | `scripts/audit_gripper.py`、`results/gripper_audit.json`、原始测量 CSV、开合曲线 |
| 未通过回退 | 修正 `zhixing_gripper.py` 的 `init_qpos`/constraint；**不使用微调掩盖机械或仿真错误** |

### N2 — TCP 与相机几何重标定

| 项 | 内容 |
|---|---|
| 进入条件 | N1 通过（几何可复现） |
| 验证动作 | ① 重新测量 ZhiXing 的 `grip_site` 与**实际指尖夹持区**的相对关系；② 重新测量 `T_cam2grip` / `T_grip2cam`；③ 渲染腕部与外部视角，量化 ZhiXing 在画面中的**占比**是否与 Panda 接近；④ 必要时为该夹爪**独立求解初始姿态**（不照搬 Panda 的工具安装变换） |
| **通过判据** | (a) ZhiXing 专属 TCP 定义与相机契约**有数值、有渲染图**；(b) 初始位姿在 ZhiXing 下自洽（IK 残差 ≤ 0.5 mm / 0.2°）；(c) 明确回答「PandaGripper 下的对齐结论是否仍然成立」——预期**不成立**，需给出新数值 |

### N3 — 抓持能力验证 ★ 闸门 G0→1

| 项 | 内容 |
|---|---|
| 进入条件 | N1、N2 通过 |
| 验证动作 | ① **10 次空载开闭**重复性；② 6 个方向末端小幅平移 + 旋转；③ **明确物体位置下的抓取 → 抬升 5 cm → 保持 2 s → 放回**；④ 记录成功与失败，不只存成功 |
| **通过判据** | (a) 抓持 **≥ 9/10**；(b) **无穿透、无数值发散**；(c) 成功是真抓持，**不是推碰、不是初始摆放导致的伪成功**；(d) 空载开闭重复性一致 |
| 证据产物 | 抓持报告、`raw/{success,failure}/` 原始记录、失败类型清单 |
| 未通过回退 | **回到 N1/N2 修物理模型与控制**；方案明确禁止「用微调掩盖机械/仿真错误」 |

> ⚠️ **本节点的最大方法学陷阱**：不能用 π0.5 策略的 0/10 来判定夹爪坏。策略装上 ZhiXing 后会**恒输出 +1 闭合**（视觉 OOD），无论夹爪好坏都抓不到。**N3 必须用脚本专家 / 直接底层控制**产生动作，才能把「夹爪能不能抓」与「策略想不想抓」这两件事分开。

### N4 — 采集链路 + 单任务试采 ★ 闸门 G1→2

| 项 | 内容 |
|---|---|
| 进入条件 | N3 通过（≥9/10 抓持） |

| **通过判据** | (a) **每一帧为「动作前观测 o_t + 实际执行动作 a_t」**，无时序错位；(b) 双相机内容**确实不同**，不得用同一图像伪装两路；(c) 抓持是真抓，非推碰/摆放伪成功；(d) 失败轨迹保留于 `raw/failure/`，**不进入初期训练集**；(e) 可回放，动作范围与单位（m / rad）合理 |

| 项 | 内容 |

## 6. 最终验收口径（不可放松）

- **范围**：LIBERO Spatial 10 个任务 × 每任务 20 个独立保留场景 = **200 次正式测试**。
