# 3090小数据LoRA验证方案

2026-10-04；lora_20261004_r1。服务器3090 24GB、系统内存约32GB。原采集/转换冻结版本、控制器、场景与审核规则不改；新工作独立置于3-lora-validation。

从已有pi05_libero权重继续适配ECO65＋ZhiXing。使用JAX原生LoRA：gemma_2b_lora与gemma_300m_lora；仅lora参数参与梯度与优化，视觉编码器及所有非LoRA参数冻结。该冻结范围比官方示例严格，明确作为24GB小数据验证配置，不宣称与全参训练等效。batch=1、horizon=10、关闭EMA，保留原pi05_libero的discrete_state_input=False，不额外转换OSC增量。

只用已验收train 9条/5226帧计算OpenPI归一化。validation 3条/1721帧隔离；保留test不参与。本轮先100步对第一条训练轨迹的8个均匀取样位置做过拟合检查，再200步从完整训练数据均匀抽帧做短程微调。原生flow matching损失、随机噪声、训练增强和梯度更新继续使用生产代码；训练与验证固定评估样本/RNG在训练前登记。

验收：实际GPU前后向运行；loss/grad有限且非零；只有LoRA权重改变；8个固定训练样本的固定噪声评估平均loss目标下降至少20%；验证loss独立报告；checkpoint保存、独立进程重载、固定输入/噪声动作输出误差≤1e-5，并验证优化器/步数可恢复。未达到的指标如实记录，不修改阈值。计划小规模仿真闭环检查作为附加结果，不将低loss等同高任务成功率。

正式运行记录真实退出码、逐步loss、GPU峰值、源/数据/基础权重指纹。资源不足时保留失败证据，并建立新版本调整资源方案，不覆盖冻结源码。训练配置、归一化与checkpoint写入唯一新目录，禁止覆盖。关闭W&B远程记录，不上传数据或权重。
